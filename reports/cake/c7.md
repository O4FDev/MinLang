## What it does

`compiler/stages/loop-versioning.min`: a `for` loop already versioned on the position
(`first >= 0`, `limit <= length`) now also accepts an access at `position + offset` where the
offset is a literal or a value the loop computes identically every iteration (a checked
`add/mul` chain is recomputed in the test block with **wrapping** arithmetic — a wrapped
offset only makes the test stricter, and the copy still computes the index with the region's
own checked arithmetic, which traps exactly as before). Non-negative offsets are tested with
`limit <= length - offset`; negative literal offsets are rejected (attempt 10/12). The access
becomes a plain load/store **only in the fast copy**; the checked copy is untouched, so an
uncovered index reports `List position P is outside its length of L.` from the same access
(`tests/list-access.min` asserts this at O0 and O2, plus the test itself and the absence of
any access call in the fast copy).

`compiler/stages/effects.min` + `runtime-abi.min`: the guard's `@.minyar.list.length` /
`@.minyar.list.values` calls are rewritten to the header loads a `parallel` function already
does at entry (`%argument.N.length`, `!range`-annotated, and `%argument.N.values`), so the
guard loads nothing and the test uses the bounds LLVM already reasons about. That rewrite is
what turned +0.4% (attempt 11) into −9.3% (attempt 8).

## Guarantees checked

- Identical failure behaviour: guard failure runs the checked copy; the fast copy's accesses
  cannot fail (overflow-safe test). Byte-identical output for every benchmark at 1 and 4
  threads (`check-benchmarks-compare`, `check-benchmarks-bothmodes`).
- Checked overflow, bounds checks, cleanup pauses, Unicode indexing, determinism: untouched.
- API/docs unchanged. `tests/list-access.min` learned the values helper (3 header helpers
  stay 3; one values helper with its own contract) and the window behaviour.
