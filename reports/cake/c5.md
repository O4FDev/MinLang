# c5 — T5 regions: mechanism landed, inference wall measured

**Summary (5 lines).** Landed a function-scope *allocation region* end to end: the compiler marks a function whose whole
graph belongs to the call, deletes its ownership scaffolding, and the runtime frees the region's heap pages in one step.
The page-region adds **zero cost** (json/logstats/treewalk/config/exprparse/matrix/nbody are Ir-identical to base and all
22 compare programs print identical output) — but it is **opt-in** (`MINYAR_REGION_LOCALS=1`) because the static proof
that decides *which* functions qualify still leaves inventory crashing, and on these benchmarks it finds almost nothing:
every hot function returns a reference, so the accepted set is 0–2 functions and the Ir delta is +0.0% to +0.4%.
The prize is real and unchanged (bulk free = −30% to −76% Ir per `reports/tradeoffs.md`), and one finding below is worth
more than my target: **a single predictable branch in `rc_heap_allocate` costs 5.9–9% Ir on json/logstats under LTO**.

Branch `goal/cake-c5`: `663771786` (region mechanism, opt-in) and `a7e041b0d` (launcher plumbing). Not a winner; no gate.

## Why the inference stops at the benchmark set

Rejection reasons are dominated by one wall: a function that returns a reference. In these programs the hot allocating
functions (`parseLine`, `parseValue`, `readUser`, `json.decode`, `Interpreter.call`) all return records/Lists/Results, so
a function-scope region would free the very value the caller keeps. The caller-side variant ("wrap the call, consume and
drop the fresh result in the same block") is blocked by the same programs: exprparse's loop stores an error `Text` built
inside the parse into `messages` (`main.min:164,170`), json keeps the decoded document, inventory keeps the ranked list —
so a sound inference needs per-value flow-sensitive escape analysis, not a local proof. Everything I could land locally
is either empty (attempt 7) or unsound (attempts 8/9 still crash bytecode and inventory), which is why the flag is off.

The landed mechanism is the part that matters for the next attempt: the runtime side is finished and free. What is
missing is a whole-program escape/borrow analysis (freshness + non-retaining summaries + flow-sensitive escape), i.e. the
compiler work `docs/runtime-memory.md:67` records as not implemented — the multi-week item, not a 2-hour one.

## For Luke: the opt-in form (2 lines, measured ceiling)

```minyar
// today: 749 Ir per call — one List header + buffer, retain/release, queue, polls
function g(i: Integer): Integer { let f: List<Integer> = []; f.add(i); f.add(0); return f.length + i }
```
```minyar
// with a scope the compiler can trust: bump-allocated in a region, freed in one step, no RC
function g(i: Integer): Integer { region { let f: List<Integer> = []; f.add(i); f.add(0); return f.length + i } }
```

Escaping a `region` value is a compile error, so heap safety stays static; region exit is allocator work (outside the
cleanup budget), so the bounded-pause contract is untouched; Unicode, checked overflow, bounds checks, determinism and
live patching are unaffected. This is a language feature (one keyword + a scope rule), which is Luke's call — the
measured ceiling is the ablation column in `reports/tradeoffs.md`: exprparse −75.8%, inventory −69.0%, treewalk −68.9%,
config −45.5%, logstats −29.2% Ir, i.e. the arena runtime's win without its memory blow-up.

## Cross-lane finding (worth more than my target)

The heap fast path cannot afford a branch. Adding `if (region_active) return region_allocate(bytes)` to
`rc_heap_allocate` (plus an `owns()` guard in deallocate/resize) cost **+9.0% Ir on json and +7.6% on logstats** even
with the region never entered; outlining the helpers got +6.3%/+4.1%, `__builtin_expect` +5.9%, and `always_inline` made
it worse (+8.0%). matrix/nbody (allocation-light) were unaffected. The cause is LTO de-inlining the allocator at ~14M
call sites on json. Consequence for c6's U12 fast path: it must stay **branch-free and inlinable**, so any per-allocation
policy has to be selected by call target (a separate symbol) or by swapping heap state — never by a flag test inside
`rc_heap_allocate`. That is exactly why the kept design detaches the class lists at region entry.

## What landed (files)

- `compiler/stages/region-locals.min` (new): the proof, the quiet/borrow summaries, value/taint tracking, and the rewrite
  (`minyar_region_enter` after the entry label, `minyar_region_leave` before every `ret`, ownership bookkeeping deleted).
- `runtime/minyar_system_small_heap.h`: page-backed regions — entry saves the five class heads and starts fresh pages,
  exit unlinks and frees the region's pages (one sparing page per class for reuse), pages created under a region are
  never returned to libc mid-region.
- `runtime/minyar_rc.h`, `runtime/minyar_cycle_rc.h`: arena no-ops so the compiler arena and tooling still link.
- `compiler/compiler.min`, `build-support/compiler.mk`, `minyar`: `--region-locals` (default off) and
  `MINYAR_REGION_LOCALS=1` to pass it through the launcher.
