# c13 — Text `+` chains, sort comparators, natural record sorts

READY FOR GATE: cb99d4793

Summary (5 lines)
1. Every Text `+` chain (3+ parts) now compiles to the same exactly sized builder as interpolation: no runtime
   `minyar_interpolate`, no `join_textN`, no boxed slots; a hot chain is 2x fewer Ir and 12–15% fewer on a 3/4-part loop.
2. `@minyar_compare_slots` is declared `readonly`, so LLVM shares one three-way compare per (a, b) pair: `a < b` then
   `a > b` is one compare. sortrows −27.2% Ir, sorttext −15.2% Ir, everything else unchanged.
3. Natural record sorts (`xs.sort()`) use the emitted per-call-site merge with the record's derived compare (no thunk).
4. A call-free literal comparator's merge polls recovery once per node instead of per comparison (callbacks and record
   sorts keep the per-comparison poll).
5. No API or documented-behaviour change; all outputs byte-identical; the three bugs the checks found on the way (`is
   not Ordered` lost, duplicate emitted merge names in cached modules, an undeclared `minyar_compare_slots` in a derived
   compare) are fixed and covered by checks.
