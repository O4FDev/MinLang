# c12 — Map lookups at hashbrown cost (target U2 rest)

Status **win** — READY FOR GATE: eb4caf1ac (branch `goal/cake-c12`, box L). All 22 compare programs
output-identical; no program more than 0.03% worse by Ir; bothmodes Ir identical at 1 and 4 threads.

## 5-line summary
1. Built-in-key Map entry points were never inlined: `minyar_map_has` alone was 29.3% of intmap's Ir. They
   are now `always_inline` (the shape `minyar_rc_release` already used), and insert/remove/backshift are
   force-inlined too, so the probe becomes straight-line code in the caller and the general paths stay out of line.
2. (b) A `has`/`getOr` miss now remembers the empty bucket its probe ended at, its hash, the capacity and a
   per-thread mutation epoch; the following `m[k] = v` inserts there with no second hash and no second probe.
   That fuses `if m.has(k) { … } else { m[k] = v }` and getOr+set in the runtime, so no code-shape matching.
3. Text keys shorter than 8 bytes hash inside the inlined probe; longer keys call the unchanged out-of-line
   hash, so every hash value (and therefore iteration order and the goldens) is unchanged.
4. (c) Scalar Maps (no reference keys or values) allocate bucket arrays uninitialized and zero only the hash
   column — `map_grow`'s memset was 5.45% of intmap. Reference-holding arrays still zero and flag every field.
5. Rejected after measurement: inlined long-Text hash, a 4-entry memo, and two micro-tightenings (all made
   intmap or wordfreq worse). A remembered Text slot is now tied to the key's hash: a freed key's address can
   hold another Text, and the memo matches keys by identity.

## Guarantees
- **API/behaviour unchanged**: no new entry point, no signature, no doc change. Hash function, load factor,
  growth doubling and the bucket layout of reference-holding maps are untouched, so iteration order is pinned
  exactly as before (all 22 compare outputs and the bothmodes outputs byte-identical).
- **Memory safety**: uninitialized key/value slots are read only when that bucket's hash is set (hash 0 = empty);
  scalar bucket records are `RC_SCALAR_RECORD` so no reference-flag byte is ever assumed; arrays holding
  references still zero and flag every field. Bounded-RC byte accounting in `map_grow` now uses the real
  per-field size.
- **Absence memo is only a proof replay**: it is used when the epoch is unchanged (every insert, grow, removal
  and clear bumps it), the capacity matches, the bucket is still empty, and for Text keys the stored hash still
  matches the key (keys equal in value always hash alike, so a match is still the same probe run).
- **Diagnostics kept**: the active-read guard (`a Map cannot be mutated from its hash or equality method`),
  `Map key is absent.`, NaN key rejection and the scratch-slot fallback are untouched.
