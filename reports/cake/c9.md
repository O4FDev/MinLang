# c9 — T7: parallel tasks that allocate records and Text, race-free (2026-10-31)

Status: **partial**. No compiler or runtime change landed (nothing that would risk the ownership contract was
landable in the time box); what I produced is (1) probe evidence pinning exactly which managed work is rejected in
which parallel construct today, (2) a working *prototype program* of the design's target shape (per-worker shards
built with managed `join` tasks: worker-local `Map<Text, Integer>`, `Text`, `List` creation, owned per-shard
results, one ordered merge) that is byte-identical to the current textindex and measured at 1 and 4 threads, and
(3) the design write-up with the concrete landing plan. Guarantees: unchanged — nothing touched them.

## 1. What is rejected today, and what already works (probes, `reports/c9-probes/`)

Branch `goal/cake-c9` (= `goal/cake-base`, which already contains the `parallel2` lane's managed join tasks
f476437ec + heap handoff 83c5c739e and `addAll`).

| probe | construct | result |
|---|---|---|
| p1 | `parallel for`, read a captured `List<Text>` element | rejected: "shared values may only be scalar buffers read by index or through .length; managed values cannot escape or be changed" |
| p2 | `parallel for`, call an ordinary function on a captured `List<Text>` element | same rejection |
| p3 | `parallel for`, **create** a `Text` local from a scalar capture (`Text(values[index]) + "!"`) | same rejection (the local itself is a reference type) |
| p4 | `join` branch builds a `Map<Text, Integer>`, returns an Integer | **works** (prints 10): worker-local Map/Text/List creation and use already runs on a pool worker's own domain |
| p5 | `parallel function` | unchanged: pure parallel functions still may not allocate (no ownership frame) |

So the gap T7 asks about is now precisely one construct: **`parallel for` bodies** (and, by the purity proof,
calls they make). `join` already is the "task that can allocate records and Text while keeping race freedom" — it
is copy-in / move-out, per-branch domains, non-atomic RC, and the joining thread adopts the stolen branch's heap
pages instead of copying the result.

## 2. Prototype: sharded index build, the target shape written with today's `join`

`reports/c9-probes/proto_shard.min` is textindex's dictionary + posting build written the way C1's design says a
product would write it if `parallel for` bodies could allocate:

- `join` splits the corpus by line boundaries (`build(first, after)` → `build(first, mid)` /
  `build(mid, after)`, byte cutoff 65,536, ~128 leaves on a 5 MB corpus);
- each branch owns its documents, decodes `Text` words, keys its own `Map<Text, Integer>` dictionary and appends
  per-term posting runs (`List<List<Integer>>`) — all allocated on that branch's domain, RC stays non-atomic;
- results move out as owned `List<Shard>` (a plain record of Lists, sendable): `left.addAll(right)` at each level,
  and the joining thread adopts the workers' heap pages (no result copy);
- the serial merge is once per shard and term (`addAll` of a run), not once per token.

Output on the 5 MB workload (68,022 documents, 713,855 tokens, 33,871 terms, 713,625 postings) is **byte-identical**
to `benchmarks/bothmodes/textindex/main.min` at `MINYAR_PARALLEL_THREADS=1` and `=4` (`diff` empty), including the
`widest`/`digest` lines.

## 3. Measurements (box H, 5 MB input, 68,022 documents)

| variant | T=1 Ir | T=4 Ir | serial work in the build loop |
|---|---:|---:|---|
| textindex today (`parallel for` tokenize + serial dictionary loop) | 525,112,719 | not measured | one Map op + two `add`s **per token** |
| prototype (`join` shards + ordered merge) | 3,382,680,491 | 3,383,537,120 | one Map op **per (shard, term)** + one `addAll` per run |

Cachegrind Ir, deterministic, no bench lock (box H load 9.8 at the deadline, so no wall column is claimed). The
prototype is **6.4x more Ir at one thread**: not a win, and the three reasons are the design's real constraints,
measured:

1. **Corpus copying.** A `join` copies every managed argument per branch (documented: "Text, Bytes, List and record
   arguments are copied into the call; pass index ranges or `FrozenBytes`"). With 128 leaves that is ~135 MB of
   memcpy here. `FrozenBytes` has no `text.decode`/`slice` path, so words cannot be decoded from a frozen buffer —
   a shared frozen graph is only half usable until Text construction can read it without a `Bytes` copy (C3's
   missing half).
2. **Per-word `Text`.** 713,855 `text.decodeOrStop` calls, each a Text header plus its character-offset table,
   against the fast path's FNV hash straight over the bytes.
3. **Per-shard term tables.** 128 shards x up to 33,871 terms x 2 empty Lists — ~8.7M tiny allocations — which is
   what a per-worker *domain* has to make cheap (region/arena allocation inside the domain), not only legal.

The structural result stands: today's fast path must keep the dictionary and posting appends on one thread (84% of
textindex's one-thread Ir per `reports/serial-and-parallel.md` C1); the prototype moves that work onto the pool with
no new language feature, but pays more than it saves. What the language still cannot do is the form T7 asks for —
`parallel for d in 0..documents { ... }` with allocation inside the body — because the body is not a task, and that
is also the form that avoids (3): an iteration uses a window and an owned per-chunk output, not per-shard tables.

## 4. Design: what `parallel for` needs to become a task (landing plan)

Reference capabilities (Pony `iso`/`val`/`ref` + ORCA), mapped onto Minyar's existing runtime:

1. **The domain already exists.** `MINYAR_THREADED` makes every RC/frame/collector/heap global
   `_Thread_local`; a pool worker is its own domain with no work needed (`reports/parallel2.md` C1 note).
   `runtime/minyar_join_tasks.h` already enters a foreign domain before running a stolen branch
   (`rc_join_enter_foreign` / `rc_join_leave_foreign`: drain, set aside frame/chunk caches, swap the small-heap
   page set, adopt on return). A `parallel for` *chunk* is the same shape as a *branch*: the missing pieces are
   (a) per-chunk enter/leave in `parallel_chunk` (`runtime/minyar_parallel.h`) — but only for loops that allocate,
   (b) the outlined worker body must keep its ownership calls: `parallelWorkerBody`
   (`compiler/parallel-outline.min`) currently **deletes every line containing `@minyar_rc_`**, which is exactly
   the assumption "worker code performs no ownership operations".
2. **`iso` in, `val` out.** Iteration bodies would take scalar captures and `val`-like borrows (already: scalar
   buffers, records of scalars, captured `Bytes` views) and may create managed values of their own (`iso`). They
   may not store one into a capture (all capture writes are already restricted to `capture[index]` with scalar
   element types), may not return one, and may not pass one to a parallel function. That is a straight
   generalisation of the current checker: `checkParallelBody` in `compiler/parallel-compiler.min` rejects every
   reference-typed local today (`else { allowed = false }` for `capture < 0`); the change is to allow a local whose
   *initialiser* does not read a capture of managed type, and to reject the escape set above.
3. **Ordered owned results** (`ref`-owned per-iteration output without a shared mutable List): the existing
   `addAll` + per-chunk result Lists, or a `reduce`-like ordered concatenation of per-chunk results, so the merge
   is per chunk, not per iteration.
4. **Bounded cleanup.** `docs/bounded-runtime-contract.md` promises bounded pauses on the owning thread; a worker
   that allocates must drain its own deferred releases at each chunk boundary (`rc_thread_domain_drain`, already
   written for join tasks) and must not hand its pages to the caller (nothing escapes). Without this the change
   would trade the shape of the serial phase for unbounded worker memory — that is the one guarantee that a
   prototype must not bend, and it is why I did not ship the compiler half.

## 5. Why this is `partial` and not `win`

- No compiler/runtime change landed, so no before/after Ir on `textindex`/`mapreduce`; both modes are unchanged
  (nothing to regress: the branch is `goal/cake-base` + this report).
- The prototype shows the design's shape is already expressible through `join` and is byte-identical, and gives
  the measured cost of that shape; it does not remove the per-token serial loop from `textindex` itself.
- The remaining work is the four items of §4, in that order; the risky one is (1b): keeping ownership calls in the
  outlined worker body also requires the exact-ownership fixture (`check-parallel-for` runs at O0/O2 with the
  ownership contract) to cover worker-side allocation, which is a test-design job of its own.

Papers used: `papers/pony-deny-capabilities-2015.pdf` (deny-capability algebra behind step 2),
`papers/pony-orca-gc-2017.pdf` (per-actor heaps that become per-domain heaps here — Minyar already has them).
