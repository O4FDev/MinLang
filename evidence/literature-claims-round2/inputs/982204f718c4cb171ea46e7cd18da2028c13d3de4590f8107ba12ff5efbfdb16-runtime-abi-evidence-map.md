# Public core-runtime ABI evidence

The current source inventory has **105 public `minyar_` entry-point names**:
93 literal definitions and 12 names generated by four Bytes-width macro
invocations. Conditional implementations share a name. The
[machine-readable map](runtime-abi-evidence-map.json) records each signature,
source location/hash, profile qualification and concrete mapped evidence.
[The generator](runtime-abi-map.py) performs a static inventory; it does not
compile, preprocess or execute the runtime, or assert exported symbols from an
object file. The frozen main runtime hash remains
`c4e78f59096e0af8926c8d06febb9277e8c7cb7e5de8fc63b907d3afb613fcb4`.

This first conservative mapping explicitly links direct native correctness
oracles for 26 entry points, allocation/work observations for 11, and paired
workloads containing four. These sets overlap. **There are no isolated
function-time measurements in this map.** A workload containing `join_text` and
`text_length` does not assign its elapsed time separately to either function.
An absent mapping means this explicit registry has not established that evidence;
it does not mean the function has never been tested.

Every entry distinguishes source inventory/review, direct correctness, count
profiling, workload timing and available test-source mentions. Source mentions
can be declarations, test wrappers, conditional or unused calls; they grant no
execution credit. Conversely, a Minyar test can invoke an ABI function without
spelling its C name, and the Bytes fixture can invoke token-pasted methods. Thus
absence of a literal source mention is not a coverage gap by itself.

| Area | Explicit evidence in this mapping | Remaining measurement or proof limit |
| --- | --- | --- |
| Borrowed/consuming Text joins and indexing | Final Unicode native/generated matrix; ASCII scan/allocation counts and generated paired workloads | No separate latency for individual calls; unknown/Unicode/no-query controls remain essential. |
| List creation, reference marking, add and appended construction | Native ownership/content oracle, allocation counts, finite-pool debt and paired growth/append workloads | Most other List access/replacement functions have test-source references but no per-function count/timing profile here. |
| Scheduler/frame/root APIs and records | Explicit bounded kernel/public operations, poll work/recovery and selected record/size guards | Private detach probes are not pure public-operation equivalence; current soak aggregate call totals do not certify every function/path. |
| Bytes | Selected size/trap guards and rejected growth-policy counts | Macro-generated widths have known existing fixtures, but this map does not upgrade a source mention or a broad suite result to per-function profiling. |
| Integer/Boolean formatting | Real generated HUD call/allocation/cache counts; Boolean/view baseline counts | Character/Float public formatting has no mapped timing; existing Float private-formatter counts cannot be assigned wholesale to its public wrapper. |
| Text equality and aggregate `joinText` | Available semantic tests and documented public ABI | Dedicated equality input distributions and aggregate-join allocation/work profiles remain absent from the explicit count/timing map. |
| Arguments, files, output, scalar checks and libm wrappers | Current public bodies/platform and boundary conditions read; existing suites remain separately scoped | No new per-entry timing or Windows-path execution here. The earlier full-gate log is not final-source whole-suite certification. |

The highest-value next baseline families are Text equality (identity, length
rejects, short fixed-width boundaries and early/late mismatches), aggregate
`joinText` (empty/single/many pieces, unknown/ASCII/Unicode, surviving aliases),
and public Float/Character formatting allocation and lifetime behavior. Each
requires an actual workload and independent contents/accounting before any
optimization proposal; source appearance establishes no performance benefit.
External file/output latency belongs to an explicit end-to-end experiment.

The [earlier full-gate disposition](profiling-full-gate-normal-disposition.json)
and exact log retain successful specific stack, Bytes, numeric, scalar and file
recipes alongside a cold-bootstrap timeout. They preceded the final ASCII
change. This map deliberately does not infer current per-function branch
coverage from that broad gate or from earlier source-line coverage percentages.
The ongoing fixed soak is likewise ongoing evidence, not a completed pass or a
measurement of continuous within-epoch memory maxima.

Native package exports are enumerated separately as outside this core evidence
scope; their application oracles and PNG review belong to the native lane.
Compiler parsing, analysis, code generation, arena application behavior and
toolchain integration also have separate evidence. Nonprefixed link-visible
allocation/arena/copy helpers are implementation helpers, excluded from the
public `minyar_` ABI inventory. This boundary prevents compiler/native evidence
from silently inflating core runtime coverage.
