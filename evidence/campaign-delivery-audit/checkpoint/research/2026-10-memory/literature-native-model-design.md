# Native ownership and scheduler differential campaign

This campaign fills a specific gap in the existing tests: `bounded-runtime.c` randomizes raw allocator blocks, while its managed graphs and frame/temporary retirement scenarios are fixed. The new replay combines valid shared DAG mutation with interleaved public frame and temporary-owner transitions. It does not repeat allocator interval fuzzing or claim to test compiler ownership inference.

`tests/research-native-model-oracle.py` maintains immediate logical roots, active frame locals/temporaries, and record/List edges. Reachability comes from graph traversal, never runtime ownership counts, dead tags, queue lengths or work counters. A child must already be logically live. Constructors can point only at preexisting objects, while later mutations independently search for a child-to-parent path and reject exactly those edges that would close a cycle. Older parents can safely reference newly constructed children. Dead nodes cannot be resurrected. Invalid premises stop generation and are tooling failures, not runtime bugs. Each operation's post-state live IDs and payload digest are serialized before native execution.

`tests/research-native-model-replay.c` interprets the same valid operation tape using actual constructors, List/record mutations, retain/release, local/move/take, enter/leave, borrow/keep/step and explicit poll entry points. The only private read obtains the existing local pointer before the public move operation; no private queue detachment or scheduler simulation supplies the runtime state. The target logical-live set is installed before a destructive operation, so an immediate destructor and deferred polling obey the same logical transition. New constructors are registered before initializing edges. Their existing owned count and the preexisting child owners protect initialization.

The runner copies runtime sources into an isolated directory and inserts an observation call immediately before managed header deallocation: one bounded destructor location and two eager locations. Exact anchors must match. The observer uses fixed static arrays, performs no allocation or runtime/service call, and does not mutate runtime metadata. Error diagnostics run only after a detected failure. Normal observer work changes elapsed time, so this is correctness testing and is unsuitable for latency comparisons. A static pointer map associates an address with its newest monotonic generation; reuse requires the old generation already be observed dead. This prevents stale pointer/address equality from conflating objects.

After every operation, replay checks every logically live record/List payload against the independent digest and rejects live frees. The record scalar tag and every reference identity participate; repeated aliases, null references and mutation all affect the digest. The runtime object counter is only a secondary consistency check against observed construction/destruction counts. Live and logically dead but physically retained generation sets are separately recorded at every step. These retained sets may still have positive physical owner counts; the oracle does not equate logical reachability with deferred physical uniqueness.

Every explicit poll checks actual observed destructions <= reported work <= min(request, K), including zero and oversized requests. Automatic public allocation/service hooks are executed normally; their aggregate operation cost is not incorrectly limited to one K. Final logical roots and frames are empty; the runtime must make positive draining progress, destroy every constructed generation, and recover all object bytes and system/pool allocations after explicitly releasing the permitted frame cache. The one-million-poll watchdog detects a bounded test failure; it is not a proved runtime liveness bound.

The boundary prefix includes a 129-edge mixed record (crossing bitmap/cursor boundaries), a 65-element repeated-owner List, sparse local slot 8 in a nine-slot frame, and seventeen borrowed temporary aliases (three chunks). Seeded continuation independently varies all fourteen transitions, nested frame sizes, repeated edge replacement, aliases, nulls, and poll requests. New objects and owner transitions continue throughout; increasing steps is not merely replaying the prefix.

Tooling followed red then green checks: six initial ownership/digest tests against unimplemented transitions, two deterministic generation/premise tests, one old-parent/new-child DAG and indirect-cycle test, one exact logical census test, and three hook-preservation/anchor tests against an unimplemented hook inserter. Logs are `build/research-native-model-{oracle,generator,tooling}-{red,green}.log`. These expected tooling failures establish no production defect. Native calibration now passes: `build/research-native-model/run-4zv0y9or/results.json` records system/K1, seed39752, 357 valid operations, 64 objects, 13 address reuses and exact heap recovery. Four compiled semantic mutants are detected: missing borrow retain causes explicit LIVE FREE; missing local retain corrupts a logically live queued List payload before header destruction; omitted retired frame owner visit fails exact final recovery; K+1 oversized poll exceeds the poll bound. A build failure or timeout cannot count as detection. The first attempt (`run-nfvjs22b`) had a binary output path colliding with a snapshot directory and therefore four invalid builds, while its correct replay passed. After correcting the path, `run-rt4bq771` compiled all mutants but initially left the explicit live-payload diagnostic unclassified. The final rerun uses the corrected classifier and preserves both earlier artifacts. These tooling defects are not runtime findings.

Limits remain explicit: single-threaded C ABI, acyclic records/reference Lists, bounded frame sizes and graph generation count, no cycle collection, no forged Text metadata, no OOM/fragmentation admission guarantee, no generated-code ownership-inference proof, and no real-time wall-clock claim. Other completed fixtures cover Unicode reuse and tight-pool admission. A failing seed retains source hashes, operations, native tape, per-step live/retained sets and diagnostics for triage; premise-valid minimization is required before attributing a new failure to production.
