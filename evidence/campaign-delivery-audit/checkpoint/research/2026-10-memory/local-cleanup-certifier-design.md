## Proposed interface and trust boundary

Future inputs: saved `.ll` bytes, an arbitrary entry-symbol selector, and a reviewed **runtime ABI/profile summary catalog**. The selector is not a whitelist. The catalog names runtime symbols with exact prototypes, source hashes, cited extents and effects; it contains no application function summaries, body patterns, source strings, work=4 constant, or expected-answer file. No compiler metadata, language annotations, new syntax or LLVM execution is needed. The optional provenance package supplies source/compiler/runtime identities; it cannot supply the inferred work.

Future output has two outcomes: `conditional_component_certificate` or `rejected` with instruction-span reason codes. A certificate is explicitly quantified over valid invocations satisfying its inferred external representation/protection requirements and listed environmental premises. It is not an unconditional contextual certificate. Missing caller evidence remains `required_not_discharged`, never silently true. A request for a context-closed or process-closed conclusion must be rejected by this prototype. Failed parsing/effect checking produces no numeric certificate, including when the old hand answer is known.

Runtime source identity is legitimately fixed for the summary theorem; application body identity is not an acceptance criterion. Record a digest of every analysed body as provenance **after analysis**, including transformed research inputs. Profile mismatch or changed runtime sources requires renewed summary review. Default prototype profile is the archived 64-bit system incremental K32, no arena/stack-owner ABI/eager cleanup. Other budgets/profiles are not inferred by this version, even if this little identity would generalize.

The checker proves membership and an ownership projection for its parsed subset under C-summary/LLVM premises. It does not verify all LLVM, all C, all linking/interposition, optimizer preservation, stack success or allocation success. Hashing the runtime object is identity evidence, not proof that a C summary refines its machine code.

## Supported grammar and CFG, version 0

Use a token lexer and a complete small typed parser for every selected definition. No regex search for a constructor or a closing suffix; no permissive unknown-instruction skip. Tokens track original byte offsets/line spans. Whitespace and semicolon comments have no semantics; quoted module strings must be lexed correctly when indexing unrelated globals/bodies. Reject malformed framing, duplicate/conflicting symbols, duplicate SSA/block names, missing targets/terminators, signature mismatches, non-dominating uses, extra operands and trailing tokens.

**Module indexing** balances tokens/braces and records all declarations and definition signatures so hidden/shadowed runtime definitions cannot acquire catalog effects. Unselected bodies are framed but not semantically validated; the output names that limit. The initial saved dialect has opaque `ptr`, unquoted ASCII identifiers, no target/datalayout directive, no attribute groups or metadata. Accept only the inspected profile's 64-bit ABI as a premise; do not infer it from absence of a target line. Selected definitions may use `internal` and `alwaysinline`; runtime failure declarations may use `cold noreturn`. Any other selected attribute, calling convention, address space, inline assembly, operand bundle or call modifier is rejected. Unreferenced static global strings/records may be indexed opaquely, but no selected function may address a global. Aliases/ifuncs or alternate definitions of catalog symbols are rejected at module level.

The finite instruction grammar is the following typed family; names are arbitrary:

| Family | Accepted forms and side conditions |
| --- | --- |
| Types/values | `void`, `i1`, `i32`, `i64`, `double`, opaque `ptr`, and `{i64,i1}` only for the three overflow intrinsics. Decimal integer and decimal/scientific finite Float constants, boolean literals, SSA operands. No `undef`, `poison`, null pointer operations or aggregate constants in selected bodies. |
| Scalars | `add/sub/mul/and/or/xor/ashr/sdiv/srem` at inspected integer widths; `fdiv`, `sitofp i64 to double`, `bitcast i64 to double` or reverse, typed `icmp` (`eq/ne/slt/sle/sgt/sge/ult/ule/ugt/uge`), `fcmp olt`, scalar `select`, and `extractvalue {i64,i1}` at index 0 or 1. **Owning root:** one entry block, one matched call-depth guard pair, exactly one heap `rc_enter(0)`, any finite number of supported fresh scalar List constructions/scalar appends/keeps and approved borrower/scalar calls, one closing suffix, `ret void`. The first two instructions must be `stack_enter` then `rc_enter(0)`; the only guard leave follows ownership leave in the closing suffix. No branch, owning loop, reference local, record constructor or second ownership activation in this version. Reject nonzero owner-slot counts: zero written locals is inferred from absence of local-owner calls plus `enter(0)`, not guessed from unused allocas. Scalar aggregates initially means scalar **Lists**; scalar records are an extension requiring their own review and are rejected now.

**Borrower/scalar callees:** no managed construction, RC operation, explicit poll, pointer store/return, backing mutation or opaque external call. Optional balanced call-depth guard at entry/returns. Acyclic branch CFGs and one reducible scalar counted loop per definition are supported. `put`'s external Bytes writes are supported on acyclic paths, but forbidden inside a loop. All syntactically CFG-reachable paths are analysed, regardless of a constant test; no hopeful pruning hides an ownership effect. Helper backedges must meet the next rule. Unreachable blocks in a selected definition are also parsed and checked for forbidden effects; version 0 rejects them if their semantics cannot be classified.

**Only supported loop (CFG rule K):** exactly one natural loop with unique preheader/header/latch, no nested loop, and all paths either exit by a scalar return or reach the sole latch. A private i64 counter cell receives zero in the preheader, is loaded/tested by signed `counter < limit` in the header, and receives `counter+1` exactly once in the latch. No other counter writes. A second private cell stores the immutable limit, whose value is an inferred `Length(p)` of an immutable scalar List borrower; no later writes. Header true edge dominates the loop body; latch dominates every backedge. Any private loop-index copy must be a direct copy of the header counter and never reassigned before use. Loop calls are read-only borrower/scalar helpers, with zero managed/guard/poll effects; no guard enter/leave inside the cycle. All raw slot reads still satisfy their own unsigned bound guards inside the access helper.

Infer the requirement `0 <= Length(p) <= LLONG_MAX-1`. It is discharged for a fresh List's constant length, or remains an explicit input requirement for an external List. The invariant at the header is `0 <= counter <= limit`; the returning/continuing body cannot change limit or pointer representation. On a continuing path `counter < limit`, increment is representable and decreases `limit-counter` by one. Thus the loop performs at most `limit` iterations, with possible earlier scalar returns. For actual `pick`, limit=2. No broad loop solver, interval widening, loop execution or bounded unrolling is proposed. A changed step, mutable bound, effectful cycle, unknown bound provenance, extra backedge, ownership-changing call or unmatched guard rejects the body. Proving only that its output type is scalar is insufficient.

## Exact finite analysis and transfer rules

**A0, resolution.** Index signatures, find the selected root's complete direct call closure, reject recursion or unresolved targets, then analyse callee definitions bottom-up. Catalog effects attach only to matching declarations, never to same-named definitions. Impose resource limits (8 MiB input, 128 selected definitions, 256 blocks per definition, 20,000 selected instructions); exhaustion means `analysis_limit`, not partial acceptance. These are analysis bounds, not program resource bounds.

**A1, domains.** Allocation generation is `(root, constructor instruction span)`, never numeric address. Root state is `(guard phase, frame phase, G, active chunk sequence, producer set, phase)`. Each `G[g]` has `kind=ScalarList`, exact nonnegative length, exact geometric capacity, token location `Producer(g)` or `Chunk(c,j)`, and `sealed` bit. Pointer SSA provenance is singleton `Param(p)`, `Fresh(g)`, `LengthLens(p)`, `BackingLens(p)`, `SlotLens(p,index)`, or private scalar `Cell(a)`. There is no unknown-pointer acceptance state. One managed owner exists per g; repeated SSA uses are borrows, not extra owner tokens. Backing lenses exist only inside read-only helpers and cannot survive a mutator call. Reject all pointer casts, memory aliases or merges not covered by these lenses/direct parameter substitution.

For borrower CFGs use a finite product domain: (i) definite initialization set of scalar cells; (ii) scalar tags `Constant(k)`, `Length(p)`, recognized loop `Counter/Limit/Index`, or `OtherScalar`; (iii) pointer singleton provenance and List/Bytes role requirements; (iv) guard depth in `{0,1}`; (v) finite effect set `{ReadList(p), WriteByte(p), NeedsProtected(p), MayTerminate}` and bad-effect flag. SSA results refer to their static definitions; no value-range enumeration. Scalar loads/joins lose differing tags to `OtherScalar`; do not propagate numeric induction through that join—K supplies the separately checked loop invariant. Return tags are the common tag of all normal returns or `OtherScalar`.

**A2, joins/fixed point.** Entry facts seed a forward worklist. Definite initialization joins by intersection; effects/requirements by union. At a join, live pointer facts and guard depth must agree exactly, else reject. Constants/tags join by equality-or-`OtherScalar`; loop-special cells are governed by K, not an optimistic constant join. Use finite sets of program sites/parameters and constant/tag vocabulary; no generated terms or growing counter intervals. Every iteration monotonically removes definite/tag facts or adds effects. Uninitialized/unreachable facts are distinct; recompute until the finite fixed point, then validate every reachable use against the final facts. Validate K/dominance independently before accepting any cyclic CFG. All normal returns must restore guard depth zero. No owner/chunk state ever crosses a branch: the owner root is straight-line.

**A3, scalars and cells.** Scalar instructions propagate scalar tags only; arithmetic generally returns `OtherScalar` (fold literal-only operations exactly if used for a structural constant). Any ptr/int conversion, scalar encoding of a pointer, scalar-to-pointer conversion, incompatible cell operation, uninitialized load, or cell-address escape rejects. Approved length/slot loads yield scalar payloads and are governed separately by A4. Overflow intrinsics yield scalar pair fields, not memory effects. Their exact LLVM arithmetic/poison semantics remain subject to valid-execution premises. In particular unchecked division/shift validity is not established by an effect summary; the actual check helpers are inspected, and normal successful invocation remains conditional.

**A4, lenses/borrowing.** A length lens imposes `ScalarList(p)` and emits `ReadList(p), NeedsProtected(p)`; length load returns `Length(p)`. Loading backing imposes the same role, creates only `BackingLens(p)`, and its slot may only be read after the bound guard above. Loaded slot words are scalar because caller instantiation proves `ScalarList`; cannot reinterpret arbitrary reference Lists as scalar. No owning token changes. Borrower calls substitute actual singleton provenance into callee effects/requirements and preserve all owner locations. Local fresh arguments require their active chunk token; external arguments emit a required continuously protected owner outside the selected frame. Two same-role read-only formals may alias through known substitution; inconsistent List/Bytes roles reject. Fresh distinct generations cannot alias each other or an initially live external borrower under the allocator/valid-heap premise. No general alias solver is claimed.

**A5, guard/frame.** `stack_enter` moves local guard 0→1, `stack_leave` 1→0; guards do not add RC frame tickets. For the owning root, `rc_enter(0)` activates a fresh **activation** f, sets written=0, temporaries empty, F+=1, and may service outside work before activation. Cached physical frame reuse is a new activation ticket. All approved application helper calls have net guard zero and no RC-frame effect, so f remains the current ownership frame. Duplicate/missing leave, nested activation or step before activation rejects.

**A6, construction.** `list_new()` in active f creates fresh g with kind ScalarList, length/capacity=0, token `Producer(g)` and no V/F. The constructor's preallocation service cannot reference the not-yet-created generation. `list_add(g,s)` requires an unsealed fresh generation, scalar s and the still-valid single producer token; increments exact length. On growth compute the system geometric policy from L:29–69 using checked mathematical arithmetic, including `LARGE_LIST_CAPACITY=4096` from T:182–188; reject size/capacity overflow. This version freezes construction at first keep and rejects later append/mutation. Backing resize is raw storage, not a managed descendant/ticket. Catalog summaries mark possible preallocation service without assuming zero debt.

**A7, keep.** `rc_keep(g)` requires `Producer(g)`, transfers that token once without retain to the active frame's tail chunk, marks g sealed, removes it from producer set, V+=1. If no chunk or tail occupancy=8, create a fresh logical chunk c, F+=1; append at its next physical slot. Use exact chunk packing from R:327–346, not a guessed one-chunk constant. Keep's preallocation and postregistration polls cannot visit an active chunk. Duplicate keep, keep of borrowed parameter, missing current frame, or later owner use as a producer rejects.

**A8, automatic service.** Before the closing boundary, constructor/backing/keep service is recorded as `may_service_outside`; it neither consumes local tickets nor changes g's token. Justification: every g has a positive producer or an owner in an **active**, unqueued chunk; no preexisting task can own a newly created nonescaping generation. No incoming scalar word can create an owner edge. This is a symbolic protection argument, not a simulation of pending queues. An unregistered producer is permitted internally during construction, but disqualifies a certificate boundary. No partial aggregate is visible at public call-return boundaries under the summaries; internal C publication steps remain trusted summary premises.

**A9, boundary discovery.** Require the terminal instruction sequence `rc_step?; rc_leave; stack_leave; ret void` in that exact order, with the step optional and exactly one ownership leave; calls have the exact void signatures. This is the maximal accepted closing suffix. Choose the first instruction of this suffix, not a hard-coded line number. Require no producer, all fresh owners sealed in active chunks, no pointer exports, and all helper calls finished. Reject earlier RC step/poll/release or partial service of the selected component: this version cannot infer an exact remaining cursor after prior local service. A suffix beginning with `rc_leave` alone is also valid since leave detaches temporaries. Record boundary policy; do not silently move it when asked for an unsupported intermediate point.

**A10, closure transfers.** At t, V is chunk occupancy sum; F is active chunk count plus one active heap-frame activation; Q=R=E=0 for the selected component. `rc_step` requires f active and guard depth one: detach each existing active chunk once and clear the active temporaries; **tickets are conserved**, then automatic service may consume an unknown subset. Mark detached owners unusable in emitted code. `rc_leave` requires f active and guard depth one: detach any still-active chunks and retire f with zero written locals, then automatic service may consume a further unknown subset. No subsequent pointer use, creation, retain, mutation, keep, scalar/helper call or registration is allowed in the suffix. Do not subtract an entire poll return or budget from local W. Closing calls are analysed for promised retirement and total obligations, not for exact post-poll state.

At full service, every detached slot is one V visit; dropping its sole scalar List owner destroys header/backing inline; empty c consumes its distinct F; f consumes its distinct F whether cached or freed. These constitute a bijection from tickets to component-attributed future units. Under eventual service, **Wcomponent(t)=sum occupancy + number of chunks + 1**. No separate List-length charge is added. An invariant/trust proof must establish A0–A10 rather than merely implement the arithmetic formula.

## Arithmetic, provenance and required proof obligations

Use mathematical integers during analysis, then prove every output/structural value representable in the declared 64-bit profile. Require `0<=length,capacity<=LLONG_MAX`, `capacity*8+sizeof(RcData)<=SIZE_MAX`, geometric multiplication legal under L's checks, and `V+F<=SIZE_MAX`. For chunk arithmetic use `n//8 + (n%8 != 0)`, not unchecked `(n+7)//8`. Reject analysis-counter overflow, truncating input constants, unknown structural arity, or exceeded parser limits; never wrap/saturate and still emit an exact certificate. The selected List capacities are 4/2 in the system profile; this affects representability only, not W. Exact local token ownership word is 10 and requires no unbounded retain count.

Outside `rc_pending_count`, heap counters, stack depth, pointer tags/alignment and allocator pointer arithmetic remain explicit valid-state/representability premises: static local arithmetic does not prove them for the process. Scalar `nsw` is accepted only at K's proved increment; other scalar semantics/traps/poison are subject to normal valid execution. No arbitrary scalar interval or full program termination theorem is supplied. The positive source domains tile14, px/py0..15 give an independent valid path expectation, not a computed full-domain safety guarantee.

Required obligations for the future prototype:

1. **O1 parse coverage:** typed parsing of every instruction on every selected path; symbol resolution, dominance and CFG reconstruction cannot hide an effect behind lexical variants, unreachable blocks, duplicate declarations or comments. This is not LLVM verification outside the declared subset.
2. **O2 runtime refinement:** each P summary matches all normal branches of the exact C/profile and ordered hidden polls; ownership publication/constructor protection, no reentrancy, correct linking and optimizer preservation remain conditional unless separately proved.
3. **O3 borrower induction:** A1–A4 fixed point is a sound effect overapproximation; immutable List lenses cannot outlive backing changes; every normal return balances guards and exports only scalars. K's invariant/rank covers every backedge/early return.
4. **O4 generation/owner conservation:** induct A5–A8 over prefix instructions. Every successful fresh constructor has one producer, keep consumes it once, all subsequent List uses borrow from active protection, no callee changes current ownership frame, no outside pointer/owner can refer back to g.
5. **O5 boundary/suffix:** A9 finds a stable all-registered boundary and checks its actual continuation; A10 retires exactly these chunks/f, with no later incoming ownership or escaped alias. Returned fresh or external aliases invalidate this subset, including retain-before-return sequences.
6. **O6 cost correspondence:** each remaining occupied slot/chunk/frame activation has exactly one operational visit/finalizer, scalar death is cocharged, cache reuse/retention uses activation identity, and automatic polls count within W without asserting attribution of their whole returns.
7. **O7 external continuation:** Bytes representation, continuously live protecting caller token during all forwarded reads/writes/service, and separation from fresh g are requirements. Actual caller hand provenance is documentary evidence; automatic call-context discharge is out of scope. Full service after return is an additional liveness premise.

## Output certificate and scientific acceptance plan

The future certificate must contain: schema/analysis version; input and analysed-definition digests/spans; profile/catalog IDs and P references; discovered boundary; constructor generations/kinds/lengths/token intervals; chunk ordered slot membership; frame activation/written count; inferred application borrower effects/K witness; local V/F and exact W; explicit external parameter representation/protection requirements and discharge status; full-service/valid-execution assumptions; O obligation statuses; reject reasons; and nonclaims. Body hashes describe analysed bytes but do not decide acceptance. [Expected derivation](evidence/local-cleanup-certifier-design/expected-derivation.json) is an independently authored expectation for a future test oracle and must never be read by the checker.

For this case the expected certificate has producer intervals IR1044→1048 and IR1049→1054, active-chunk protection thereafter through `pick`, external `WriteByte(argument0)` forwarded via `paint/put`, no fresh escape, t immediately before IR1057, chunk `[A,B]`, written=0, V2/F2/W4. Caller protection status remains required with separate manual Build-slot0 witness. The conditional empty-outside-debt K32 schedule is step=3 then leave=1, but the prototype should **omit schedule predictions**: shared external debt can consume automatic budgets, so remaining work at return is unknown. A `remaining_after_return` exact value or `ceil(4/K)` process-poll field is forbidden.

The TDD proposal is [preregistered data](evidence/local-cleanup-certifier-design/tdd-plan.json), **not tests already written/run**. Expectations come from S/IR/runtime hand reasoning; transformations are independent new thought controls, not copied checker rules or runtime observations. Parent coordination would authorize only standalone research checker/test/fixture files in this evidence lane, reading saved IR; no compiler changes, regeneration, metadata, native execution or builds.

Implement in gates: first a complete subset parser/resolver with rejection tests; second body-derived acyclic borrower/lens summaries; third K with independent invariant review and adversarial loops; fourth owner/producer/chunk/boundary inference and JSON output. A stage that cannot handle K must report the archived positive as rejected, even if simpler hand fixtures pass. Validate future inference on archived input plus lexical renaming/whitespace variants, owner-count/packing variants with **changed numeric answers**, and semantic negatives. A broad parser, application allowlist, assumed noescape attribute or answer-cache is a rejection of the proposal itself.

Future red calibration should mutate the **checker** independently to (a) assume all application calls pure, (b) allow double keep, (c) ignore a callee backedge effect, (d) omit chunk/frame finalizers, (e) count List elements as visits, (f) return zero after automatic polls, and (g) bypass body analysis on the original name/hash. The corresponding semantic/metamorphic controls must fail. Do not test only an implementation's internal serialization against itself. Plan one adversarial review of the rules/expected fixtures before code, then parser/effect/inference tests under parent-authorized bounds; a pass would establish only tested prototype behavior plus its conditional proof argument.

**Useful result remains open.** This design would automate a genuine allocation-site/owner/borrower derivation in a tiny subset if it survives those gates. It would neither optimize production nor infer general memory automation. CTRC and Niu–Hoffmann already occupy generic lazy counting, resource inference and continuation-sensitive reasoning. Potential value is inexpensive inspection of Minyar's actual emitted hook sequences; corpus coverage, maintainability, diagnostic usefulness, measured analysis overhead, production benefit and novelty are unresolved. A sound rejection of the real loop/caller requirements is preferable to declaring a string-matching validator an inference result.
