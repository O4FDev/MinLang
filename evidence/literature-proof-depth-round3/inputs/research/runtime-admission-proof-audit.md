## Allocator proof attacked

**Ordered lists, including both links.** Allocation chooses the least nonempty adequate class and removes its head; each split inserts the upper half at the next lower class's head. `pool_insert` writes the new node's `(NULL,head)` and the old head's predecessor; `pool_remove` repairs both neighboring links and clears the map start ([pool](evidence/runtime-admission-proof-audit/inputs/runtime/minyar_pool.h), lines 89–115, 152–185). Removing a temporary split-chain head therefore restores the old head's null predecessor and every old successor link, not just relative order.

At a move from an original region of order j to target r>j, replacement allocation removes/splits only classes >=r. It cannot alter the original region's class-j tail or any lower list. The old region was removed as a head. Freeing its temporary lower block consumes its remaining split-chain nodes and head-inserts that same region before its unchanged original tail (pool 205–223). Thus every departed region restores its exact ordered position. Previous departed regions have already been restored; the next selected original region has strictly greater order. This closes the induction through arbitrarily many moves. No address sorting or singleton-list assumption is needed.

**Crossing a region.** Its lower base is aligned to every class within the region. Within-region growth finds the exact upper split chain. For growth past order j, either target alignment fails, or the scan reaches the original region's order-j sibling. A free exact sibling contradicts canonicality; a larger aligned dyadic free block covering that sibling also contains the original region, contradicting disjointness. A subdivided sibling has no exact order-j free map byte. Other temporary growth has not freed outside storage. Therefore that scan fails. Alignment is by pool **offset**, as the C source specifies, not an assumed absolute P-aligned base (pool 267–273).

**Failed validation and overlap.** The entire upper-buddy scan precedes all unlinks, charge changes and poison changes (pool 267–285). Failure changes only work telemetry. Replacement is allocated while the old block remains allocated; valid partition disjointness makes the two requested copy ranges nonoverlapping. `memcpy` precedes the old free (pool 290–317). Replacement splitting cannot occupy the old region or trigger a merge across its original boundary. The lower-buddy discard algorithm is a different transition and remains excluded (pool 323–395).

**Final class selection.** Before selection of a region of order >=f, all visited regions have order <f. The original lists at classes >=f are untouched. The selected region is consequently the same least-class head chosen by direct F allocation. Its remaining split chain after growth to f is precisely the chain from direct splitting to f. Restored regions, every map interior, all ordered links, mask, boundaries and current charge agree. A final contiguous block after common header service guarantees replacement success even during old/new overlap; summed free bytes would not suffice. No successful post-state theorem is made for a failed construction.

## Runtime and scheduler correspondence

The 64-bit List layout is statically asserted: 24-byte payload, 8-byte ownership prefix, 8-byte data prefix ([runtime](evidence/runtime-admission-proof-audit/inputs/runtime/minyar_runtime.c), 63–74; [RC](evidence/runtime-admission-proof-audit/inputs/runtime/minyar_rc.h), 27–30, 109–157). Result header allocation is common and calls service **before** requesting its 32 bytes. The guard is tested after `minyar_list_new` returns ([collections](evidence/runtime-admission-proof-audit/inputs/runtime/minyar_collections.h), 201–216). There is no second service after that allocation. The proof boundary includes both successful common service and successful common header request.

For fixed, non-arena scalar construction, `references=0`, result kind is RC_LIST and source length n is valid and nonnegative. Both schedules use capacities 3,7,15,...; requests are exactly `8+8*c=32*2^i` (collections 29–87). The original fragment grows the empty destination fully before copying (frozen original, 183–198). Current code does the same with one reservation. Scalar stores, including either tail-transfer flag, return without retain/drop/poll (collections 104–145). No growth is needed while filling n+1 slots. Each final RcData header stores `8*cf`; ownership headers, initialized slots and RC requested-byte totals agree. Slot/reference maps and frame allocations are not secretly required for this phase.

Representability must cover `n+1`, every `2*c+1`, `8*c`, and the extra eight header bytes. The source checks these separately. F<=P on the supported fixed 64-bit configuration also bounds allocator shifts, class encoding and used-byte addition by a valid partition. The theorem is arbitrary finite-depth mathematics; its C correspondence is confined to representable supported configurations, not every hypothetical machine width or depth.

**Zero count is a conservation invariant, not a state reset.** At a valid service-return boundary, pending count counts captured/recent/active objects, detached frames and detached chunks. Enqueue and all three completion paths maintain it; carried unary-child ownership is published before poll returns ([bounded RC](evidence/runtime-admission-proof-audit/inputs/runtime/minyar_bounded_rc.h), 69–74, 121–190, 219–250, 269–315; RC 305–316). Validity includes disjoint queues, truthful counts, valid ownership and no counter corruption/overflow. It follows that zero count leaves no queued/active task, but active frames, their temporary chunks, cached frames, cursor residues and scheduler parity can still exist.

Idle `rc_service_pending` returns before calling the scheduler and only zeros testing `rc_bounded_last_work` (RC 95–100). For a direct `minyar_rc_poll` with valid zero count, `work=0`, both unit loops execute zero iterations, `if(work)` does not update `rc_bounded_next_queue`, recent parity/cursor/queue fields stay untouched, and the only persistent write is last-work telemetry (bounded RC 256–373). This holds for any budget, including zero and clamped oversized budgets. Idle service preserves all latent decision state; it does not normalize it. Since no scalar operation creates retirement tasks, omitted services cannot change frames, cache charge or chunks.

**An operation that invokes a poll need not be inert.** `rc_step` first detaches active-frame temporary chunks (RC 399–403); `rc_bounded_retire_temporaries` increments pending count (bounded RC 121–129). With one active chunk holding one ordinary owned scalar object, initial pending_count=0 does not stop `rc_step` from enqueuing that chunk and then dropping/freeing its owner and retiring the chunk. This is not an admitted theorem-phase operation: intervening calls are expressly excluded. Frame entry/exit, releases and stack-frame leave also perform work before/around polling. No whole-hook identity follows from the idle-poll lemma.

**Telemetry is excluded carefully.** High-water is read in its own update branch; testing steps are read to accumulate step metrics. They therefore influence bookkeeping control flow, contrary to an unrestricted claim that they are never read. They do not affect class/head selection, growth validity, coalescing, cache decisions, scheduler selection or request responses (pool 59–70, 152–185, 278–317). Last-work, object/byte counts and text-decode counters are similarly telemetry. `rc_bounded_cached_frame_bytes` is **not** telemetry: it is consulted by cache admission (bounded RC 227–237) and must remain equal in Q. Active/local indices, temporary counts, frame/chunk links, ownership, scheduler parity and cache roots all remain included. No forced include, fault injection or custom testing hook that feeds metrics into requests/control is covered.

## Continuation wording to make explicit

No failed mathematical lemma was identified. The smallest useful correction is to define the word **legal**, rather than enlarge the continuation claim:

> On the supported fixed, non-arena, single-mutator ABI, take matched valid canonical states after identical successful result-header service and allocation. Let the protected source be a scalar List with valid initialized slots, set references=0, require fresh NULL result backing, representable capacity/header-inclusive requests, no intervening operation or reentrancy, and at least one original free block of final order f or higher. Direct reservation and geometric construction both succeed and end with equal allocator decision state, live runtime headers/initialized semantic data and complete ownership/scheduler/cache state. Every finite continuation built from the specified raw allocation, preserving resize and free transitions, using valid owned allocation bases and bounded copy extents, and selecting requests only from common responses/addresses and initialized live semantic data, returns equal admission responses and addresses. Writes used to initialize later visible data must agree. Telemetry, stale/free/spare bytes, sanitizer internals, OS residency and timing are outside the observation relation. Fatal failures terminate the trace; no recoverable failed-state relation is asserted.

A continuation needs a live-allocation table with requested extents and an initialization mask (or an equivalent logical ownership predicate). Raw allocation exposes uninitialized storage; resize preserves only the permitted initialized prefix; growth does not initialize new bytes. `old_size` must describe an accessible old requested range, not exceed the live allocation, and not expose stale spare values to future request choices. Successful allocation alone cannot turn every underlying byte into common semantic data. Scalar result slots `[0,n+1)` and the headers are initialized; spare slots are not. Literal C object-representation equality, including padding, is not implied. ASan behavior is not the mathematical admission observation; a separate correspondence proof would model poison/unpoison and sanitizer runtime. These are explicit formalization obligations, not a counterexample using an excluded read.
