## L: what the formal machine actually proves

**Representation and machine.** §2.2, pp 5–6 explains why lazily reclaiming several size classes cannot guarantee bounded progress toward the particular class demanded by a later allocation: a small chain can conceal large children. The basic solution is one cell size. §2.3, pp 7–8 uses 32-byte cells with an eight-byte header and at most three pointer fields in the remaining payload. An intrusive LIFO free list uses alignment bits to preserve field-count information overwritten by its link. Large source objects are split into segments. Fixed field access can be bounded when source object size is statically fixed; this does not establish bounded traversal for arbitrary variable-sized source objects. The introductory up-to-two-times representation discussion and §2.2's coarse four-times worst-case/2.66-times boxed-integer examples are different qualifications; no one multiplier applies to all representations or Minyar.

Appendix A defines an untyped functional core with explicit ownership instructions `dup` and `drop`. The baseline ignores those instructions for semantic execution; the eager reference Koka machine recursively drops descendants. The lazy machine retains zero-count cells on a free list without recursively decrementing their fields. Allocation either requests a fresh cell or pops a cell and performs bounded outgoing-field drops before reuse. Boxed/internal steps are erased when comparing program traces. This is not an arbitrary Minyar mutable-heap semantics: sound insertion of ownership instructions, positive-count discipline and eager machine soundness are premises of the comparison.

**EDA is a design extension, not another proved theorem here.** §2.5, pp 9–10 distinguishes eagerly deallocating allocations by a transitive effect. Objects reaching large allocations are dirty; eager and lazy free lists guide reclamation. If a large allocation lacks space it can drain reclaimable work without a constant-time guarantee. This is directly relevant to Minyar's unsegmented backings, but there are no EDA operational rules or soundness proof in Appendix A. §3.1 says the benchmark implementation does not implement EDA. Its idea cannot be cited as empirical validation of variable-sized bounded allocation.

**Appendix B does not close the abstract-to-C proof.** It prints a basic CTRC allocator without the locality optimization; Koka supplies header initialization/count updates separately. Page-local lists distinguish immediately reusable cells and deferred pointer-bearing cells. `pop_free` can take unused cells on the current page before a deferred drop entry; this is not literally the abstract rule “reuse whenever F is nonempty.” Page packing, slack and page-stack search need a refinement relation. The displayed allocator calls `mmap` in large blocks, tries huge pages and falls back to ordinary pages, and uses `madvise` population/advice. Those calls make the fresh-allocation abstraction visible; they do not establish hardware constant time. Reading all displayed code supplies implementation detail, not a proof or execution result.

## N: the cost semantics before the type theorem

§§2–3, pp 3–7 use a strict first-order, let-normal functional language with tuples and lists and mutually recursive top-level functions. Only cons cells allocate a heap location in the formal core; nil is a null value, primitives/tuples are not heap-boxed, and native stack/closure overhead is not the measured resource. Lists are inductive acyclic values. There is no observable address identity, shared mutation, deferred RC or delayed finalizer in this core. §1, p 2 explicitly excludes fragmentation; an ideal copying collector is offered as one way to avoid it.

A configuration is `(V,H,R,F)`: stack bindings, heap, continuation reachability, and a **set of interchangeable free locations**. Reachability is a multiset counting paths; collection tests reachable membership. Well-formed configurations cover active and free locations, protect roots, and have already placed unreachable locations in F. The collector is immediate and ideal. Cons chooses a member of F and removes it; this costs one cell. In a let, the first subevaluation protects the second expression's free variables through an enlarged continuation R; between subevaluations, now-unreachable locations are made free. Conditionals and matches similarly discard roots and collect their garbage. Operational `share` adds aliases, not physical copies.

The resulting bound is on the minimum sufficient **additional initial free cells**, beyond the already allocated input/context, for a terminating ideal evaluation. A zero overhead result does not mean zero live input storage, zero stack space, zero collection work, or no native temporary buffers. F has no addresses ordered for placement, block classes, coalescing metadata or finite contiguous-byte obligation. Minyar's equal total-free-byte states can have different future admission; replacing its allocator by this F is already a substantial abstraction requiring a separate sound relation.

## N: soundness chain, including the hard sharing case

The annotated list type supplies nonnegative rational potential per cons cell plus scalar pre/post potential. Cons spends one allocation credit plus its annotation. A destructive cons match can release its cell's potential **and one cell credit**. That release is not sound for arbitrary aliased operational heaps by itself. The analysis uses `ShareCopy`: potential splitting pays for a virtual deep copy. Ordinary HM inference, linear constraints and an LP solver infer annotations (§4, pp 8–10); collector-sensitive automated inference without hand annotations is prior art. Discussion of weighted constructors allows matched introduction/elimination constants, not arbitrary delayed-collector substitution.

**Intermediate machine.** Ecopy (§5, pp 11–12) deep-copies a value at sharing, so current roots and result trees have no duplicated heap paths. Initial linear context, disjoint current/continuation/free regions, exact free-variable domains and stability of protected continuation cells are needed. Appendix B carries the preservation argument across lets, branches, matches and copies. Runtime Minyar must not actually replace shared mutable aliases by copies: value-equivalence alone would erase observable shared writes and identity. An analysis-only simulation could still be useful, but its observational relation must be stronger.

**Why mere “copy uses at least as much memory” is insufficient.** During a let, Ecopy can free several copied cells when the shared execution frees only one or none. Comparing just `|F_gc| >= |F_copy|` at each big-step premise does not induct. Definition 6 (pp 12–13; restated as Definition 14, pp 33–34) introduces a proper partition γ from each active operational location to a nonempty disjoint class of its copied instances. It requires:

1. Context/value equivalence.
2. Class size equal to root-path reachability multiplicity **plus continuation multiplicity**.
3. For every valid subvalue path, the corresponding copied reachable class intersection has the correct multiplicity.
4. The copied continuation intersects each class in exactly the operational continuation's multiplicity.
5. The exact gap `|F_gc| = |F_copy| + Θ(γ)`, with `Θ(γ) = sum_l (|γ(l)| - 1)`.

This is an identity-aware simulation relation between machines, not an implementation census or a constant-sized runtime ledger. In particular, γ's domain consists of physical identities but its classes count their unfolded path copies; it cannot simply be identified with Minyar's one-generation work tickets.

## N: evaluation and implementation limits

§6, pp 16–18 implements the new semantics/type rules in RaML. Crucially, some OCaml-AST elaboration passes had to change because they were no longer cost preserving under the GC metric. Source transformations preserving a resource model are thus an explicit predecessor, not a Minyar novelty claim. Software covers more than the proved first-order list core, including polynomial potentials, user data types and higher-order functions. Closures remain allocation-counted rather than destructively matched/reclaimed by this analysis; the global mutually recursive function block's closures occupy a separate heap/free list. Empty user constructors allocate in the implementation although nil is null in the formal lists. These are stated abstraction boundaries, not defects invented for Minyar.

Table 2 (physical p 18, visually checked) gives inferred ideal-space bounds, constraint counts, solver elapsed times, and hand-derived optimal bounds checked by running the authors' cost semantics. Quicksort, selection sort and eratosthenes have zero **additional cell** bounds; dfs has two, bfs four, ocamlsort M+1, map_it M+1. Mergesort's inferred quadratic expression is loose versus the table's **floor(log(M))**, not M log(M). Transpose's 1+2LM bound is loose versus max(0,2L−1); pairs also retains unnecessary potential. The reported optimal formulas are not extrapolated here to undocumented tiny-input conventions. Sharing can therefore produce useful bounds or substantial conservatism. These are not measured native RSS, CPU reclamation latency, finite buddy-pool success or cost of Minyar inference. No solver or program was run by this lane.

## Source-proof translation obligations

1. **Ownership and boundary relation.** Define Minyar states only at valid public-hook return boundaries, with every producer owner represented or protected, complete queue/frame/chunk/return ownership, no unmodelled reentrancy, and generation-valid links. Translate eager/functional value relations to mutable aliases and actual observations. A hidden C-local carried child in unary fusion is semantic cursor zero despite the global sentinel; it bypasses ordinary `rc_drop`. Snapshotting globals alone misses the state needed by a proof.
2. **Cost refinement before an inferred bound.** Give an explicit transition machine for reported Minyar work: sparse frame slots still cost visits after moves/nulling; reference-record flags do not remove scalar-position visits; batching costs actual iterations and can stop early; unary fusion costs two per pair; scalar leaves are cocharged; Text views can mint one root task through a last backing decrement. Appendix N's destructive-match rebate is immediate free space, not this delayed unit schedule. Preserve this measure through compiler transformations and automatic polls, including synchronous stack visits and helper/direct poll attribution.
3. **Space and allocation as separate measures.** Model requested bytes, rounded buddy classes/ordered placement, retained backing capacities, allocation overlap, cached frames/immortals and any outside-pool storage. One Text finalizer can free a huge block; a completed frame finalizer may retain a cached frame. Neither W nor Θ is this storage measure. Fixed-cell proofs apply only after a representation theorem; Minyar does not currently segment all objects or compact its pool.
4. **Closed component versus continuing environment.** Introduce an analogue of N's protected continuation for external roots, but retain mutable ownership identity and generation. Prove that the chosen component cannot acquire new edges/tasks after the boundary and account for shared service with outside debt. A four-unit component total cannot predict the number of whole-program polls. A whole-universe ledger cannot selectively drop Bytes when Text has the same runtime representation.
5. **Open arrivals and service.** Relate actual mutations/allocations/producer intervals to latent obligation growth, service opportunities, burst envelopes and retained classes. First-mortal promotion creates large work demand; empty polling cannot prepay its latent scan. The closed certificate has no arrival/backlog theorem. Hardware latency additionally needs bounded copying/initialization, allocator/OS paths and a declared workload protocol; no timing number in either paper supplies that proof.

These are obligations, not an implementation plan implicitly authorizing stopped lanes. No new syntax is required merely to state a local static summary, but automatic useful inference remains to be demonstrated.
