# Peer memory semantics and baseline obligations

Audit date: 4 October 2026. These are primary documentation/source observations. Executable peer measurements may intentionally use older pinned versions; those are snapshot baselines, not assertions about the latest release. The selected current source commits inspected here are in [literature-snapshot.json](literature-snapshot.json). No external code in that manifest was built during the literature pass.

| Peer | Relevant automatic mechanism | Fair comparison and trap | Primary evidence |
| --- | --- | --- | --- |
| Rust | Scoped owners and borrows; optional nonatomic Rc and interior RefCell | Use Rc rather than atomic Arc for the single-mutator shared-owner case; retain actual observable mutation. Rc cycles leak unless weak edges or another collector are chosen. Also include explicit arena/iterative-drop controls when comparing graph destruction | [standard Rc documentation](https://doc.rust-lang.org/std/rc/index.html) |
| Swift | ARC with optimized ownership and access exclusivity | Separate class shared identity from value/COW collections. Dynamic exclusivity work and value copies must not be silently removed from a mutation comparison. ARC documentation does not promise uniform bounded graph destruction | [official exclusivity discussion](https://www.swift.org/blog/swift-5-exclusivity/); [ARC language reference](https://docs.swift.org/latest/documentation/the-swift-programming-language/automaticreferencecounting/) (JS page inaccessible in this pass) |
| C++ | RAII, explicit unique/shared owners and allocators | Use unique ownership, nonowning borrows and explicit arenas where semantics allow; use shared owners only where needed. Include an iterative destruction design instead of equating naive recursive destructor chains with all C++ | [C++ Core Guidelines](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines) |
| Go | Concurrent tracing with pacing and allocation assists | Report GOGC/GOMEMLIMIT, live heap, allocation rate and assist work. The memory limit is soft; CPU/service pacing is not a deadline. Fixed-memory failure semantics differ from Minyar's finite pool | [official GC guide](https://go.dev/doc/gc-guide); [pinned pacer source](https://github.com/golang/go/blob/6f5c275ebdc454197fff5f1496521c8f81e20eef/src/runtime/mgcpacer.go) |
| Zig | Explicit allocator passed to allocating operations; arenas/fixed buffers available | Useful floor for manually structured event storage. Record design effort and cross-arena aliases; resetting an arena differs from dropping outgoing shared managed edges | [official language documentation](https://ziglang.org/documentation/master/) |
| Nim ARC | Compiler moves, destructor operations, cursor inference | Test default inference rather than deliberately retaining every reference. ARC is the acyclic comparison; unowned cursor correctness matters when reproducing shared mutation | [destructor/move/cursor documentation](https://nim-lang.org/docs/destructors.html) |
| Nim ORC | ARC plus cycle collection | Keep cycle-support cost separate; current source uses Bacon–Rajan-inspired candidate processing and graph loops. No uniform per-field K bound was observed in inspected collection entry points | [pinned ORC source](https://github.com/nim-lang/Nim/blob/2ac83c7dbcb4f1c64b3f21a3ad5b9ce410881ce7/lib/system/orc.nim) |
| D | Conservative tracing; @nogc code can still use explicit nongc storage | @nogc forbids GC allocation, rather than all allocation or all destruction. Compare default GC and a manually provisioned event path separately; initialization/finalizer semantics differ | [GC specification](https://dlang.org/spec/garbage.html); [core memory library](https://dlang.org/library/core/memory.html) |
| Koka / Perceus | Precise RC, specialization, reuse; effectful functional language | Standard current runtime already handles ordinary destruction stacklessly; do not infer recursive stack failure merely from RC. Inspected large-vector path has different handling. Stack safety does not imply bounded total destruction work | [Perceus publication](https://www.microsoft.com/en-us/research/publication/perceus-garbage-free-reference-counting-with-reuse); [pinned refcount source](https://github.com/koka-lang/koka/blob/facb7932ce6871fdb063f762a304bd8238f35fba/kklib/src/refcount.c) |
| Lean | Optimized RC, borrow inference and reuse | Current cold deletion uses an explicit todo list; array deletion loops over elements. Include sharing/no-sharing and allocation counters. Lean's persistent values do not directly reproduce arbitrary shared List mutation | [Beans](https://arxiv.org/abs/1908.05647); [pinned object runtime](https://github.com/leanprover/lean4/blob/a2f95768ffe4c0717118119f3407be0bcc7b3e7d/src/runtime/object.cpp) |
| Morphic | Automatic borrow/lifetime inference with RC fallback for a pure functional language | Important annotation-free ownership baseline, but mutable identity and compiler maturity differ. Pin available compiler/harness; do not substitute a claimed paper result for a local measurement | [2026 author publication](https://www.cs.princeton.edu/~mpmilano/publication/fully-automatic-type-inference/); [pinned project README](https://github.com/morphic-lang/morphic/blob/ffe4a080efefe76316a7dd87e55d7550b48cf0d7/README.md) |

Use two workload categories: common immutable construction/read/drop operations that all peers can express faithfully, and shared mutable operations only for peers reproducing the same alias-visible results. Do not combine the two into one ranking. Timed work must include equivalent ownership, copies and retirement obligations; explicitly identify any manually tuned variant.

Preallocate inputs and validate a value hash outside the timed region. Record compiler/version/flags, CPU, allocator mode, warmup, process repetitions and paired order. Long chains probe stack behavior; broad graphs probe graph work; shared descendants probe premature reclamation; large arrays and Text growth probe copying and allocator capacity. Report eager completion and incremental outstanding debt separately, then add an explicit full-drain measurement. A fast operation that leaves large debt has completed a different amount of physical work.

For a production comparison, add bursts and fixed-capacity pressure rather than only throughput at ample memory. Distinguish maximum completed-operation pause, arrival-to-completion response including waiting, peak managed requested/rounded bytes, RSS, failure count, unreclaimed debt and recovery duration. Process exit is not evidence that a collector safely reclaimed a graph before exit.
