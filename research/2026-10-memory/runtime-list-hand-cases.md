# Canonical List reservation: two actual-runtime hand cases

The two reviewer-derived cases passed four isolated builds and eight executions: original versus guarded reservation, each at native O2 and C ASan+UBSan O1, with source lengths 3 and 7. Production source hashes remained unchanged. This checks source correspondence for these constructions; it does not prove universal admission equivalence.

[Preregistration](runtime-list-hand-cases-preregister.json), [durable results and exact commands](evidence/runtime-list-hand-cases/run-dnz5c7jb/results.json), [archive inventory](evidence/runtime-list-hand-cases/run-dnz5c7jb/archive-index.json), [fixture](../../tests/memory-research-list-hand-cases.c) and [runner](../../tests/memory-research-list-hand-cases.py) preserve the selected inputs and complete outputs. The archive contains runtime/helper/fixture snapshots, observer patches and logs; installed Darwin Clang and sanitizer libraries remain external prerequisites. LeakSanitizer was disabled; native C received both ASan and UBSan. There is no generated-language, timing or process-RSS claim from this cohort.

| Source length | Moving backing addresses, original | Final backing, both | Peak charged bytes, original / guarded | Successful allocations at append completion, original / guarded |
| --- | --- | --- | --- | --- |
| 3 | 96 to 128 | 128 | 192 / 160 | 5 / 4 |
| 7 | 96 to 128 to 256 | 256 | 352 / 288 | 9 / 7 |

Both versions use the same final capacity (7 or 15), values `[37*i]` followed by 919, requested bytes and current pool charge. The displayed allocation counts include setup and the common result header. High-water and step counts deliberately differ and are excluded from the decision-state comparison.

The first source uses ordinary scalar List creation and insertion. The second allocates source header at 0, initializes every byte of a raw 32-byte blocker at 32, allocates 64-byte guards at 64 then 128, and places the source backing at 192. Freeing guard 128 before guard 64 produces the ordered free list needed for the common result header to select 64 and split off 96. A snapshot injected immediately after that actual header allocation captures the proof boundary without manufacturing allocator internals.

Every snapshot records all 128 allocation-map bytes, every free-list head and ordered node's previous/next pointers across every allocator order, mask, current charge, maximum order, initialized List ownership/data headers and values, and the initialized blocker. Pointers are normalized as pool offset plus one, with zero for null. Free links are read through the allocator's poison-aware accessor. Reclamation state includes pending count; captured/recent/active object roots; saved cursor and scheduler turns; frame/chunk roots; active and cached frame roots; and cached-frame charge. These roots remain null in both cases. Object/requested/immortal accounting also matches.

After append, both versions receive raw allocation requests 32, 64, 128 and 4096 in that order. The last request rejects in both; successful addresses and every recorded decision state agree. Probes are freed in reverse order; source and result are released, pending work drained, and the blocker freed. Both finish with exact zero objects, requested bytes and pool charge. The continuation does not read uninitialized raw storage or invoke resize with an invalid copy extent. Free payload, uninitialized spare List slots, padding, sanitizer state, telemetry, residency and timing are outside the observation relation.

These cases do **not** exercise restoring a temporary head before an existing same-class tail. Length 7 starts with two 64-byte free nodes, but the common header consumes the first, leaving only singleton lists at the reservation boundary. This preserves a real remaining test gap; the independent audit's length-15 unsorted-list case would form a separate cohort rather than extending or relabeling these results.

The [transformation review](runtime-transformation-review.md) and [independent adversarial audit](runtime-admission-proof-audit.md) state the conditional argument and unresolved proof obligations. Idle polls preserve decision state; `rc_step` may create debt before polling. The theorem excludes intervening operations, pending retirement, existing destination backing, reference ownership effects and telemetry-driven continuations. It requires initialized semantic data and valid resize-copy extents. These two executions do not establish those premises for arbitrary caller histories or extend the theorem to system/lazy admission. The separate aggregate all-poll observer refinement has its own records and observation counts.
