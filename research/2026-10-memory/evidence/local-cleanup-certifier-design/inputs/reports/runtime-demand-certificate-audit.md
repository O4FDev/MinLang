## Premises needed for the retained result

Use the original 64-bit non-arena incremental subset: one mutator, finite acyclic allocations, truthful typed representations, preserved owning counts, representable counters/cursors/tags, protected borrows, and non-reentrant allocation/deallocation/polling. At the measurement boundary no aggregate is partly initialized and no producer or transfer owns an unregistered mortal root. Every included mortal allocation is in the supported universe, including positive-count descendants of retired slots. Every root is in active/retired frame or chunk storage. Immortal containers with mortal outgoing owners are excluded.

After that boundary permit only matched retirement of existing active frames/chunks and positive-budget polling, until every root is detached and all tasks drain. **`rc_step` is permitted as temporary detachment, not equated with `poll`.** No direct root release, new registration/retain, move transferring an owner outside the universe, allocation, mutation, Text classification/index/cache growth, or new frame activation occurs in this closure. Stack storage remains valid through its matched leave. Empty-frame cache retention/disposal is a separate storage matter.

For the five-word implementation claim strengthen “Bytes/foreign graphs excluded from the managed cohort” to either **none exists in the tracked managed universe**, or a proved uniform inclusion/separation policy. Raw allocations can remain outside the work ledger because they have no managed owner transitions. Merely declaring a mortal managed object outside the cohort does not provide a discriminator when it later reaches common destruction code. Per-cohort attribution and selective immutable-List reserve omission need additional provenance or a static separation proof, as the original report already acknowledges.

These are ABI/source premises, not properties established for all generated Minyar or arbitrary native callers. In particular scalar-record reference writes, repeated initializer overwrites of owned fields, reference-List scalar stores, cycles and releases of queued dead pointers are outside the valid protocol. The current C does not dynamically enforce every one of these conditions.

## Transition audit

Let `B0 = V + F`; let `U = V + F + Q + R + E`. The meanings of V/F/Q/R/E are those in the original certificate. An immortal-only reference List has a **mortal List header**; “immortal” describes its entries. All deltas below are mathematical signed changes to aggregate counters. Implementations must use checked unsigned add/subtract operations, with an explicit failure/unknown policy on overflow.

Two boundary qualifications make the List update table complete. Under the documented `minyar_list_references` protocol, classification happens while empty and Lists never shrink, so any reachable permanently promoted List is nonempty. If a wider valid C-state model admits an empty `RC_REFERENCES`, its first append must add both V and F. If that model permits initial classification of a nonempty scalar-kind List, `C:19–20` goes directly to `RC_REFERENCES`; instrument `+V=n,+F=1`, rather than E. Neither operation needs a new flag; both need the old length/kind. Those wider native states are not automatically well-typed language programs.

## Closed-cohort hand refinement

Assign one ticket to each remaining semantic position and nonempty aggregate/heap-frame/chunk finalization. Owner conservation counts a shared allocation once while preserving every physical owning edge. Reference aggregation does not recursively sum child certificates. Ordinary units consume one ticket; leaf destruction is cocharged with the dropping visit. Detachment/requeueing conserves tickets. The carried-child loop consumes two tickets per pair using its C locals, and the List loop consumes one per iteration. Stack leave consumes its synchronous visits in addition to the actual queued poll result. These observations give total consumed V/F tickets exactly `V(t)+F(t)`.

An owning Text root is either already queued (one Q ticket) or still live. For each initially live root r, define delta(r,sigma) by the actual future last-owner decrement: one if through view destruction, zero if through a counted direct owner slot. Flattening and no new ownership arrivals ensure r creates at most one root task. Initially queued roots and those created root tasks each finish in one reported unit. Thus, under the premises and the transition correspondence above,

```text
W(sigma) = V(t) + F(t) + Q(t) + sum_r delta(r,sigma)
V(t) + F(t) + Q(t) <= W(sigma) <= V(t) + F(t) + Q(t) + R(t).
```

One can make the telescoping argument explicit by adding to remaining V/F the currently queued Q plus the future delta of currently live roots for the fixed continuation sigma. A last-view decrement transfers one future delta into Q; a direct-last decrement removes a zero delta; queued-root finishing consumes Q. That semantic expression decreases by exactly reported work. It is a proof device, **not an implementable oracle for last-owner order**. U instead needs only conservative root tokens: direct root death can decrease U by two while reporting one visit; last-view queueing preserves R+Q; queued root death decreases it by one. Therefore subtracting poll returns alone does not maintain exact counters.

Finite acyclicity and complete root detachment are also necessary. After all tickets/tasks discharge, any remaining mortal positive-count component without an included root would require a cycle or an unmodelled owner. The valid representation/owner premises exclude both. This is a termination argument over the hand refinement, not a C safety or compiler proof. If no mortal Text exists, the correction vanishes and W=V+F. If every initially live root has only view owners, every delta is one; this premise cannot be inferred from a root's count/backing alone.

## Minimal boundary counterexamples and Text check

**External direct release changes the accounting relation.** One uniquely owned scalar record returned by a constructor, then released directly at K1, has V=F=Q=R=0 but public reported work 1 (`B:84–86,376–383`). This is not a counterexample to the original closed protocol: its external producer owner violates that protocol. It rejects extending the formula to arbitrary public releases without defining a separately charged external-drop event. A uniquely owned Text gives a similar problem: R=1 falls to zero on direct release, even though neither V nor F existed. A single added root “visit” would also overcount a direct nonleaf release's reported immediate work, which is zero; the public metric distinguishes leaf death from nonleaf enqueueing.

**Idle poll and `rc_step` differ.** An active frame with one temporary owning scalar record in one chunk and no pending tasks has V=1,F=2 (heap frame plus chunk). `poll(1)` returns zero. At K1, `rc_step` detaches the chunk and its own poll visits the temporary, recording one work unit in testing instrumentation; `rc_step` itself returns void. The chunk finalizer remains, and the frame stays active (`R:399–403`, `B:121–129,241–250`). U changes through actual service only. Empty-queue offered budget cannot be banked, and detachment cannot be omitted as if step were a poll.

**Selective mixed Text/Bytes bookkeeping lacks provenance.** Supplementary `minyar_bytes.h:41–48` calls the same `new_text` as owning Text. An ASCII Text with four initialized bytes and a Bytes value of length/capacity four can have identical header ownership (`8|RC_TEXT`), payload fields, allocated byte size and byte contents. Put one of each in a two-slot heap frame, transfer their sole owners, then compare swapping their semantic types between the slots. A ledger counting only Text has the same initial V=2,F=1,Q=0,R=1,E=0 in both. On the reverse first visit, correct R stays one when the destroyed value is Bytes and falls to zero when it is Text. The common local destructor operands and the five initial sums distinguish neither case. This is an indistinguishability counterexample to **selective Text-only accounting in an intermingled managed universe**, not to the Byte-free formula. All RC_TEXT owning leaves could instead receive a uniform conservative root token, but that broadens the definition and needs its own stated scope; selective exclusion cannot be obtained magically from five sums.

**Original two Text orders.** In the original valid K1 heap-frame fixture, slots `[root,view]` visit view first: its backing decrement leaves count one, so direct root visit destroys inline; work is two visits plus frame finalization, or 3. Slots `[view,root]` visit root first, leaving the view's backing owner; view death then queues the root, adding a fieldless unit for total 4. V=2,F=1,Q=0,R=1 in both. Automatic leave service is included in those totals. These are independent hand predictions, not observed fixture results. The slot states differ; aggregate equality is neither complete-state equality nor a telemetry equality assertion.

**Separate reported execution.** After the hand audit, the coordinator relayed that core-owner run `finalrun-vlxdii3h` passed both orders at O2 and C ASan+UBSan O1, with exact totals 3/4 including automatic K1 leave work, matched destruction identities/sparse slots/pending traces, exact managed-object/requested-byte recovery, and a separately disposed 96-byte empty-frame cache. The report also says a red observer mutant omitting automatic leave work was detected after successful recovery, and the observer stored integer identities before destruction. This is [a pinned copy of that communication](evidence/runtime-demand-certificate-audit/external-fixture-report.json), not an independently inspected execution archive. A bounded search of `research/2026-10-memory/evidence/runtime-demand*` did not locate the run; its exact saved path was requested. No fixture was rerun. The eight current production source hashes still match the frozen audit inputs. The reported result corroborates this tiny case only and does not discharge the ledger, C/compiler or broader scope premises.

## What the forty bytes establish

For the uniformly tracked supported universe, store V/F/Q/R/E in five static 64-bit words. Constructor/destructor context, existing kinds/lengths, backing pointer, sparse low-bit marker, chunk fullness/count, actual frame activation site and fused-loop C locals identify every update above. No per-allocation ticket flag or identity table is required: each construction/destruction lifecycle updates its contribution once. The absence of a graph walk comes from online maintenance since inception, **not** reconstructing the ledger from an arbitrary frozen heap or assuming an unseen live-root census.

Updates are constant-many checked arithmetic operations **per existing constructor, registration, mutation or cleanup unit**. A poll/stack leave still has its actual bounded loop; copy, index building, UTF-8 scanning and allocation costs remain outside this statement. Hook every bypass/branch, before deallocation, and keep constructor publication and fused-state observation within the non-reentrancy premise. Forty bytes describe aggregate static data, not emitted code size, temporary registers, measured overhead, WCET, physical retention or compiler inference. A bound after saturating counters is unknown/infinity; exactness is then lost.

Do not adopt forty bytes as a selectively scoped universal result. Intermingled excluded managed objects, late attachment, per-cohort accounting, type erasure, or selective immutable reserves invalidate the provenance assumptions. Five counters cannot establish that all roots close, infer length/generation bounds, or reveal the final owner kind of a mixed Text root. The no-mortal-Text recognition and compiler-to-closure proof remain separate obligations.
