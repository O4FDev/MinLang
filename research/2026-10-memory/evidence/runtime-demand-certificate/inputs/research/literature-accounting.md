Reviewed 4 October 2026. The inspected implementation preserves the owner/task accounting invariants in the cases analyzed. No additional production defect was established by this pass. The strongest result is a transition argument tied to actual runtime functions, supported by a finite executable model that compares the two batching paths with unit scheduling. This is not a mechanized proof of C, compiler preservation, allocator behavior or real-time execution.

## Scope and representation relation

Assume one mutator; valid generated ABI calls and indices; aligned live object pointers; finite successful allocations; checked reference-count failure; no foreign introduction of edges; no finalizers, weak references, concurrent collector or reentrant allocator/runtime hooks. No user code accesses retired storage. Text views are flattened to an owning or immortal Text root. Cycles are excluded by compiler construction/mutation rules. These assumptions are obligations, not consequences of passing the model.

For a live mortal object `v`, the physical count equals the number of owning edges from external roots, active local/temporary tables, live heap slots, and **unvisited** retired object/frame/chunk slots. Consumed slots can retain physical pointer bits without owning an edge. Borrowed parameters contribute their protecting caller edge, not another count. Immortals are excluded from this equation. A retired object has zero owners and belongs to exactly one object task, except for explicitly private fused state.

At quiescent transition/public boundaries:

```text
pending_count = captured queued objects + recent objects + active object
                + detached frames + detached temporary chunks
```

This counts tasks, not fields, remaining cleanup work, bytes or allocation pressure. An object with 8193 unvisited slots and an object with one unvisited slot both add one. An exhausted chunk remains a task until its separate finalization unit. Cached frames contribute neither tasks nor owners. The model explicitly checks the owner equation, unique task membership and task cardinality after individual ordinary units and after semantic fused pairs.

| Actual implementation | Representation and required invariant | Transition effect |
| --- | --- | --- |
| `rc_bounded_enqueue`, `rc_drop` | Zero-count nonleaf object; low3 kind bits; intrusive recent link; saved cursor0 | Add one object task. Existing child owners remain until visited |
| `rc_bounded_old_object_unit` | Captured batch plus separate active cursor | Consume one field or finalize one task; retain exact owner edge until the visit |
| `rc_bounded_recent_object_unit` | Recent stack with per-object saved cursor | Save incremented cursor **before** dropping a child; a newly dead child may become the new head |
| `rc_bounded_retire_temporaries` | Full non-tail chunks, eight slots maximum, exact live temporary count | Splice in constant bookkeeping; add `ceil(count/8)` tasks; clear frame chain/count |
| `minyar_rc_leave`, `rc_bounded_frame_unit` | Each written slot indexed once; moved slots remain indexed but contain no owner | Detach frame without changing owner counts; consume sparse indices in reverse; finish/cache only afterward |
| `rc_bounded_chunk_unit` | Chunk count equals its unvisited tail prefix | Consume one owner or finalize empty chunk; decrement task count only on finalization |
| `minyar_rc_local`, `_take`, `_move` | New owning edge established before old drop; lowbit records ever-written status | Retain then replace, transfer then replace, or transfer to expression while clearing table pointer; no duplicate sparse index |
| `minyar_rc_keep`, `_borrow` | Incoming owned token protects value across service/storage request | Keep transfers token to chunk; borrow first retains it; active chunks are not pending tasks |
| `minyar_rc_enter` | Reused frame has no outstanding owners/chunks; sparse-index area starts after full capacity, not current declaration | Clear declared local prefix and reset written count. Old bits outside declaration remain inert |
| `minyar_rc_leave_stack_v1` | Eligible stack frame has `1 <= declared <= 8` and `declared < K` | Visit at most `declared` written owners synchronously; detach heap chunks; poll remaining budget; never enqueue/cache stack storage |

The concrete owner oracle already used by `tests/stack-ownership-runtime.c` independently scans active and retired frame/chunk storage. The new Python model complements that native evidence; it does not replace it. Its frame cache always admits finished frames, abstracting byte limits and physical allocation. Model scalar placeholders/null slots represent ABI owner visits, not a new source null feature.

**The model isolates the ownership/scheduler kernel.** Its methods named `enter`, `new`, `local`, `keep`, `step` and `leave` omit automatic public-ABI service hooks. Only explicit `poll` or `release(service=True)` services work. Thus method names do not promise a step-for-step public API execution. Kernel traces can be replayed using preallocated protected objects, private detachment and explicit polls; alternatively a separate public-operation model must incorporate every allocation/enter/release/leave hook. In particular public allocations after an odd unary poll can drain its remaining debt before another owner queue arrives. The current trace does not predict that public sequence or allocation success.

The additional `public_enter`, `public_local`, `public_keep`, `public_step` and `public_leave` wrappers now model their actual RC pre/post service hooks. Tests exercise these at K1/K2/K5/K32, with root/view/local/replacement objects prepared before queued debt arrives. A third public-RC trace records entry, root release, view keep, statement step, explicit polls and exit. It excludes object-constructor internals and physical allocator behavior; those setup calls happen while no pending work exists. At K1 the public statement step performs the view visit itself, leaving two tasks; subsequent public polls finish the root and chunk separately. This companion gives a feasible native public API replay rather than mislabeling the kernel detach sequence.

## Work accounting

One queued unit visits one object field or frame/chunk owner, or finalizes one task. Visiting an owner can also destroy one managed leaf. A leaf destruction can perform several backing deallocations; managed destruction count and allocator-call count are different quantities. Owning Text finalization may free byte data, character-index data and header. The model counts managed destructions, not raw `free` calls.

`rc_drop` of a last Text view destroys the view, then decrements its flattened root. If the root becomes dead it is queued as a fieldless task, preventing a second managed destruction in that unit. `runtime/minyar_runtime.c` slice construction selects `text->backing ? text->backing : text` and retains that root. This concrete construction relation justifies why later queue finalization need not recursively drop another view backing.

Public release charges its immediate0/1 destruction and polls `K-immediate`. A slot-processing unit already accounts for its own possible leaf destruction and is charged once. Keep/borrow can invoke two service budgets when allocating a new chunk; the public contract explicitly allows2K there. Managed allocation/resize services K **per hook**. Record initialization, frame zeroing, capacity planning, byte copying, arbitrary expression composition and system allocator latency remain outside that cleanup cap.

The stack exit argument is exact: `written <= declared < K`, so `written + poll(K-written) <= K` and at least one queued unit remains available. Null/moved/shared/immortal written slots still cost a visit; charging only successful `rc_drop` destructions would undercount. A compiler entry/exit mismatch or escaped stack header violates the ABI assumptions and is not repaired by this arithmetic.

## Batching refinement and private ownership

The executable [model](../../tests/peer-memory-model-accounting.py) contains a unit scheduler and both production batching conditions:

* List batching runs only without a ready recent task, visits each slot separately, preserves object-turn parity and stops immediately when a drop creates recent work.
* Unary pairing requires exactly one task, no active object, no frame/chunk queues, an unvisited one-field reference record and at least two remaining units. Each pair costs two. A unique one-field child can be carried only when at least four units remain, reserving a final publishable pair. Shared, scalar, Text, null and wider children take ordinary paths.

Model differential cases cover chain lengths1/2/3/7/12, seven budgets including odd3/5/7, five terminal shapes, List runs that encounter queued nonleaves or view roots, zero-budget polls, and later frame/chunk arrivals. They compare work, object counts/owners/cursors/deadness, captured/recent/active membership, task count, scheduler parity and detached owner contents at every public poll boundary. Equal final heaps alone would be a weaker oracle.

The C fused loop's intermediate state requires care. It can destroy the current parent before replacing `rc_bounded_active` with the carried child. The next child's owning count becomes a dead tag without being linked through `rc_bounded_enqueue`, and `rc_bounded_cursor` still has the pair's sentinel1 while that child's field is not yet visited. Therefore a global-state scanner invoked inside a deallocation hook would not see an ordinary valid queue state. The refinement relation includes the carried child and its unvisited outgoing owner in the poll's C locals, interpreting that fresh child as semantic cursor0 until its next pair. No production read of the freed parent's payload occurs before the active pointer is replaced. This is acceptable under the explicit non-reentrancy assumption; it is a concrete reason finalizers, callbacks, instrumentation or concurrency cannot be added casually.

The model checks a normalized semantic boundary after each carried pair, and the final ordinary pair publishes real queue/count/parity state. It does not execute every C instruction or prove compiler optimization preserves the private-state relation. The object-only selector sets next queue1 only after actual work, matching ordinary selection after an object unit; zero/empty polls retain selector state. Competing queues disable both object-only paths for that poll.

## Conditional liveness argument

Across objects/frames/chunks, persistent round-robin selection services every continuously ready queue within three **executed** queued units, including separate K1 polls. Old object service is reserved on alternating object units. Capturing a finite recent stack prevents later arrivals joining its predecessors. Consequently an active captured head advances within six global units when all queues/classes stay ready. A task behind other captured tasks must wait for their remaining finite work; six is not a per-object completion bound. The unary-parent finalization exception advances old work and delays recent work by at most one object unit.

For a closed phase with no further mutator changes and a fixed finite heap, define the semantic unreachable closure by ignoring retired owner-table/slot edges as source roots. Let potential include one future finalization for each still allocated unreachable mortal object, every unconsumed outgoing owner/field visit that its representation will require, every detached owner visit and one finalization per detached frame/chunk. Include unreachable descendants that still have positive physical counts because a dead ancestor has not visited them. This potential is finite. Each ordinary unit consumes at least one included visit or finalization. Newly zero-count descendants become tasks but were already included; enqueueing is not an increase in this closed potential. Fair service and acyclicity ensure no unreachable positive-count SCC remains forever outside the queues. Therefore all unreachable cleanup eventually finishes if positive-budget polling continues. Frame caching retains allocator storage but no objects/owners.

This is a proof sketch over the representation relation, not a proved C theorem. It relies on no resurrection, finite arities and valid preserved owner counts. A native ABI caller can create cycles outside source checks; repeated polling then cannot reclaim that unreachable SCC. With ongoing arrivals, the closed potential argument does not establish bounded backlog or finite-pool success. A mutator may also run indefinitely without any service hook. No wall-time deadline follows from fairness in executed units.

## Capacity and counterexamples to broader claims

`pending_count == 0` means no *currently detached* work, not that the live graph contains no future retirement cost. An immortal-only reference List can be destroyed immediately. Appending its first mortal member promotes its kind to an ordinary reference List, making retirement visit the whole existing prefix, including immortal elements. A debt certificate must account for that representation transition; attributing one future unit to the first mortal append would miss the prefix scan. No service performed while the queue was empty banks credits for this later debt.

A one-task bound also cannot imply a byte bound: a single queued record may retain a large descendant backing until its final reference visit. The earlier [reservation adversary](literature-reserve-review.md) demonstrated this operationally: removing intermediate allocation service caused bounded-heap OOM where baseline succeeded at both K1 and K32. A fixed count budget plus a buddy pool supplies structural bookkeeping bounds and a capacity failure mode; it does not guarantee allocation succeeds or establish a universal live/retained-byte ratio. Service frequency, incoming arities, hidden descendants, backing sizes, caches, fragmentation and external effects need explicit workload bounds.

The closest primary precedents remain [CTRC](https://lptk.github.io/files/ctrc-2024-05-09.pdf), [RTRC](https://www.diva-portal.org/smash/get/diva2:743471/fulltext01.pdf), [frame-limited reuse](https://www.microsoft.com/en-us/research/uploads/prod/2021/11/flreuse-tr.pdf), and [Work Packets](https://www.steveblackburn.org/pubs/papers/packet-oopsla-2025.pdf). They already cover deferred edges, restricted allocation units, borrowing retention or heterogeneous GC scheduling. Their bounds cannot be transferred without matching representations: CTRC's uniform cells differ from variable-sized backing storage, RTRC's object-size dependence matters, arbitrary borrowing retains unrelated bytes, and heterogeneous work-packet items have unequal costs. The source review/status of each is recorded in [literature.md](literature.md). [Concurrent immediate RC](https://doi.org/10.1145/3656383) has an explicit concurrent reachability protocol; this single-mutator queue does not supply that protocol.

## Runtime replay obligations and current gaps

The [trace predictions](literature-accounting-traces.json) contain two kernel sequences (K1 view-root/partial-chunk and odd-budget unary chain followed by frame/chunk arrivals) plus the explicitly public RC view/chunk companion. They are model predictions, not native evidence. Independent engineering review caught a transient trace-generator error: a saved recent-list reference was mutated by later polling, making the earlier JSON step internally inconsistent. The model's tuple snapshots were unaffected. Copied capture, a permanent snapshot-independence test and regeneration corrected the artifact before native replay. Sent the engineer these focused follow-ups:

1. Temporary counts8/9/15/16/17, including a view whose last root owner disappears during chunk service. Check task cardinality, actual managed destructions and exact final heap recovery.
2. Write, move, replace and move one local repeatedly. It must have one sparse index, a null deferred visit and no duplicate decrement. Reuse cached capacities large→small→larger with unvisited stale storage outside the declaration.
3. Reference-map cursors crossing127/128 and mixed reference/scalar flags. Check low-bit preservation independently of runtime encode/decode helpers.
4. Unary fusion at odd budgets3/5, then append frame/chunk tasks. Verify all observable queue/cursor/parity/count state against an independent oracle, with shared and Text-view terminals.
5. First mortal append after a long immortal-only List prefix, exposing future scan debt despite a small task count. Separate measured cleanup from source copy work.

The model's intentional counter mutant was rejected by partial-chunk and Text-view tests; invariant checks also reject missing task counts, duplicate queue membership, a dropped owner count and prematurely advanced cursor. These tests show the oracle detects those selected errors. They do not show the production runtime ever contained them.

Two documentation precision issues were corrected after the parent released the full-suite source freeze: `research/reclamation/formal-model.md` now includes the implemented record-field mutation rule rather than listing mutable records as a future feature, and the top bounded-RC comment now describes recent-stack/captured-batch links. The [applied patch record](literature-accounting-doc-corrections.patch) retains the exact text delta. `checkFieldMutation` rejects an inserted `R -> F` edge when declared `F` can reach `R`; this extends the earlier List-only first-cycle argument. The proof sketch still does not verify every lowering/module call site. Runtime ownership coordination preceded application. Code token fingerprints were unchanged; source-map history records old/new raw hashes and the separately reviewed engineer Unicode fix outside this model's selected slice function. Fifteen model tests passed after repinning provenance.

Remaining stronger validation: native replay of the new traces, sanitizer coverage of these exact inputs, proof of compiler construction/borrow preservation, every guarded mutation path including modules, C pointer-tag/cursor layout validation, allocator/accounting refinement, and workload-specific byte/service bounds. These are explicit pending obligations rather than claims implied by model success.
