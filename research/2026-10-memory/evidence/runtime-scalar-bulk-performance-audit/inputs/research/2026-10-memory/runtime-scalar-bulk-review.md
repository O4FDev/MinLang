## Exact minimal branch and source proof

Let n be the source length. Start with the existing `minyar_list_appended` sequence (collections 201–223): create result header; optionally mark references; diagnose `n == LLONG_MAX`; select repeated growth versus reservation using the complete post-header `rc_pending_count`; prepare capacity; copy; perform the existing tail add/take. Preserve that order and every check. The candidate changes only the scalar prefix copy, after successful existing reservation, to a nonzero-length byte copy followed by publication of length n.

The branch must satisfy all of the following:

1. The caller supplies `references == 0` truthfully for a scalar List. Do not infer scalar type from pointer-looking contents, a zero member count, immortal-only contents, source ownership count, or the lack of object tasks. Reference Lists remain reference Lists even when empty or entirely null/immortal.
2. The original reservation branch was selected. In bounded RC this means **all-task** pending count was zero immediately after common successful header service/allocation. Capture that decision; do not retest after reservation/growth and activate bulk copying for an initially indebted call. In supported eager/arena builds there is no bounded debt branch, and their existing reservation remains the preparation path.
3. The result is the newly created List: initial NULL values, length zero, capacity zero; in ordinary heap profiles its kind is `RC_LIST` and ownership is `8 | RC_LIST` (10). Its kind stays scalar. No result alias escapes during construction.
4. The source is a valid List with `0 <= n <= source.capacity`, n initialized scalar slots, and adequate accessible requested storage. For n>0, source values is non-NULL. A live caller/ancestor/local/temporary owner protects the source header and backing throughout the call, including all allocation service. A pointer to an already retired source does not meet this premise merely because its bytes have not yet been freed.
5. Successful unchanged preparation yields accessible destination capacity c **at least n+1**, with all geometric/copy/header-inclusive arithmetic representable. Source/result headers and their backing ranges are disjoint live storage.
6. Single mutator, no reentrant allocator/copy/observer or user finalizer, no asynchronous runtime mutation, no intervening ownership operation or external callback. Use an ordinary supported **nonallocating** libc/compiler copy: no raw allocator request, Minyar allocation/service/callback, or recoverable failure. Test observers must record into preallocated storage without feeding requests or control back into the runtime.
7. Copy exactly the initialized n slots; skip the library call when n=0; then publish length n and execute the unchanged tail add/take once. No `restrict`, new capacity, allocator slack, service policy or ownership transfer is introduced.

**Why the eliminated calls have no hooks.** `minyar_list_new` initializes NULL/0/0 (collections 3–8); ordinary `object_allocate(...,2)` selects RC_LIST (runtime 289–291, RC 27,109–119). With `references == 0`, `minyar_list_references` is never called. For prefix position i with 0<=i<n, the old loop's result length is i and c>=n+1, hence i<c and the grow condition at collections 105 is false. In bounded non-arena builds, kind RC_LIST takes the early store/increment/return at 108–111, bypassing promotion, retain and poll at 113–118. In eager builds the retain condition at 121 is false; arena builds compile it away. There are no releases, temporary registrations, stack entry/leave calls, frame operations or callbacks in this scalar path. The surviving tail also has n<c; scalar `add_take` takes the same early return (129–145), and scalar `add` takes the established path.

The all-task guard is an authorized scope restriction, not a newly necessary lemma about these stores: once c>=n+1, even indebted scalar stores return without service. Nevertheless this experiment must leave the entire original debt fallback untouched. The broader peer wording about copying after either preparation path is not approval to enlarge this candidate.

**Capacity and multiplication.** For valid n<LLONG_MAX, n+1 is representable. `list_reserve` repeatedly computes the existing checked capacity schedule and calls `list_resize` (29–87). On success, c>=n+1 and `(unsigned long long)c <= SIZE_MAX / sizeof(long long)` (53–54), so `n*sizeof(long long)` is representable. The expression must convert n to size_t before multiplication; a signed `n*8` computed before conversion would introduce a different overflow domain. Ordinary `rc_allocate_data` also checks room for the RcData prefix before requesting memory (RC 122–131); successful non-arena preparation therefore establishes `sizeof(RcData)+c*sizeof(long long)` fits. Arena growth has its existing block/header/alignment checks (runtime 230–257). These success implications establish the copy bound; no duplicate early preflight should move existing diagnostics.

The actual growth policy remains pooled 3,7,15,... (with its existing RcData assertion), ordinary nonpool 2,4,8,... and factor-four growth above the configured threshold. Reserving only n is wrong at a cliff. No assertion about allocator-returned slack is needed or permitted.

**Source lifetime and disjointness.** Service occurs inside object/data allocation and resizing (RC 109–157), including before the source is first read by the existing appended function. A valid strong source owner survives any unrelated queued frame/chunk/object owner drop; those drops can reduce its count without destroying the protected allocation. Collection retirement frees backing only when ownership reaches zero (bounded RC 45–114); it cannot mutate a live protected scalar prefix. No allocation from malloc, the valid buddy partition, or the monotonic arena may overlap another live requested allocation. Arena source/result ranges may share an arena block, but remain distinct subranges. The fresh result did not exist during input evaluation and is not referenced by an input/debt graph. Therefore copy ranges are nonoverlapping. Existing source aliases are allowed and unchanged; source uniqueness is unnecessary. Fabricated overlapping native headers, stale pointers and lying type flags are outside the valid ABI.

Compiler source confirms `references` is emitted from the checked argument type after verifying the element type (compiler 2427–2457), and slots use i64 encoding (1399–1452). ## Scalar bits, publication timing and C assumptions

Supported source correspondence assumes eight-bit bytes, eight-byte/64-bit pointers and slots, size_t/uintptr_t widths compatible with the current headers, correctly aligned requested ranges, and two's-complement `long long` with no padding or trap representations. The runtime statically asserts pointer/slot sizes and List offsets (runtime 63–74) and the ordinary object-header size (RC 27–30); those assertions alone do not prove every additional representation assumption on an exotic C implementation. The supported ABI and truthful initialized slots supply them. No new platform support follows from this review.

The old scalar loop loads/stores `long long`; the proposed copy moves its object representation. On this ABI those operations preserve exactly the same eight bytes per slot. Integer minimum/maximum/negative values and arbitrary valid raw slot patterns remain unchanged. Boolean slots are zero-extended i1, Character slots zero-extended i32; no normalization is performed. Float slots are LLVM `bitcast double ... to i64`, recovered with the reverse bitcast (compiler 1399–1452); copy must never convert through C double, compare Float values, canonicalize NaNs, or lose signed zero/NaN payload bits. Native fixtures can transport specified raw words without FP arithmetic, including infinities, subnormals and signaling/quiet NaN representations where the supported ABI accepts the raw transport. This says nothing about later arithmetic/NaN behavior.

An ordinary nonoverlapping `memcpy` with valid accessible n-slot ranges establishes the same typed scalar prefix in allocator-backed storage; no ownership transfer occurs. Its standard copy contract plus the supported library/compiler implementation is assumed, not a reviewed proof of libc internals or sanitizer interceptors. Interposed copy functions that allocate, poll, reenter, or inspect a half-constructed result are excluded. The new call can change instrumentation or other private library state, so unrestricted raw C-context equality is not claimed.

For n=0 a fresh source can have NULL values (collections 3–8). Do not invoke `memcpy` with that NULL pointer even for zero bytes. An empty source with previously allocated spare capacity must also work. Skipping the copy leaves length zero; the tail path writes slot zero and publishes one, within existing c>=1.

For n>0 the old loop publishes lengths 1 through n, whereas the candidate publishes n after the entire prefix is initialized. Intermediate destination payload/length states and add-entry instrumentation histories differ. Neither routine can poll, allocate, drop, call user code or throw a Minyar error in this capacity-sufficient scalar phase. With no escaped result or reentrancy, no admitted runtime observer reads those intermediate states. Both reach the same initialized prefix and length n before the unchanged tail path; both finish with length n+1 and the same last word. This is equivalence at phase/public-call boundaries, not equality at every machine instruction, debugger breakpoint, hardware fault or profiling callback. Publishing n before copying would destroy the clean initialized-length invariant and is rejected.

## Allocation, diagnostics, service and future admission

The two compared programs are **current guarded reservation plus old scalar loop** versus **the same guarded reservation plus bulk scalar prefix**. Their common constructor, kind decision, LLONG_MAX diagnostic, post-header all-task guard, capacity calculations, allocation/services and error paths are identical. If common header allocation fails, neither reaches the later overflow check; preserve that priority. If overflow/capacity/header-size/backing/pool/sanitizer-limit failure occurs, it occurs before copying in both. Fatal `minyar_stop` prints and exits (runtime 190–197); no recoverable failed-state equivalence is asserted. Under valid success premises the scalar prefix and tail cannot raise a new capacity/retain diagnostic. A fallible or allocating custom copy is outside the proof.

No allocation, resize, free, managed helper or public poll is removed by replacing the scalar prefix calls. Their old capacity/kind tests only lead to stores and increments. The tail add/take stays. Therefore request order/sizes, service offers/results, object/data headers, allocator decision state, physical counts, pending queues, cursor/parity/turn state, active and detached frames/chunks, cache roots and **decision-relevant cached-frame charge** are preserved. Active temporary owners may exist despite pending_count zero; neither copy path detaches them. In particular, `rc_step` would detach temporaries before polling (RC 399–403, bounded RC 121–129), so introducing, moving or replacing that operation would invalidate this argument. Idle `rc_service_pending` may write test last-work telemetry (RC 95–100); its calls are unchanged here, not silently omitted.

Stack ownership does not create a hidden copy-phase hook either. The separate stack ABI links a valid caller-supplied active frame at entry, and leave detaches heap temporary chunks, drops written locals and polls before returning (stack frames 22–71). The scalar copy calls neither entry nor leave. Stack headers/owner tables cannot be sent to deferred queues/cache; a source protected by one must remain live through the paired leave, and leave cannot occur inside this non-reentrant copy phase. Compiler placement/optimization validity is a stated preexisting ABI obligation, not proved by this review.

From matched post-reservation states, the copy phase does not execute any allocator transition. Complete fixed-pool map, every free-list head and both ordered links, mask/current charge/allocated boundaries and all RC decision state consequently remain equal. After the same initialized result is published, every finite legal raw allocation/preserving-resize/free continuation with common requests, valid allocation bases, valid copy extents and decisions based on common responses/addresses/initialized live data has equal fixed-pool admission responses and normalized addresses. Subsequent requests cannot depend on the differing append-entry/copy observer counters, transient lengths, spare/free/uninitialized bytes, padding, sanitizer internals, errno/library-private state, OS residency or timing. Newly admitted raw payload must be identically initialized before reading it or using it to choose another request.

**Relationship to the earlier theorem.** The queue-empty buddy theorem compares older repeated geometric preparation to direct reservation. It proves a narrower allocator-decision/initialized-data relation, while high-water and allocation/step telemetry can differ; its fixed canonical pool, contiguous final free-block, representability and legal-continuation premises remain necessary. The two hand replays and adapted unsorted replay are bounded source-correspondence checks, not universal proof. For the new suffix rewrite, preparation is identical, so those allocator lemmas are unnecessary: both start the copy at the same decision state. Composing the old theorem with this suffix argument preserves its original fixed-pool admission consequence without weakening any premise. It does not extend the old geometric-versus-reservation theorem to debt, references, libc admission or lazy physical commitment. References and initial-debt cases here stay literally on the old path.

The local no-allocation/service argument also applies to ordinary configured system/eager/arena/lazy copy phases under their valid storage and copy assumptions. It supplies no guarantee of OS/libc allocation success, residency, timing or physical commitment. An end-state source argument is not formal C/LLVM verification. No complete raw C state equality or global collector/admission theorem is claimed, even if ordinary runtime allocation telemetry happens to match for this newer comparison.
