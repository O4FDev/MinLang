# Standalone SHA-256

`use "sha256" as sha` imports a streaming SHA-256 package independent of
`crypto` and `securecrypto`. It uses `runtime/native/sha256.c` and OpenSSL
`libcrypto` on 64-bit Linux, macOS and Windows. The implementation requires
OpenSSL's `SHA256_*` compatibility API; an OpenSSL build that removes deprecated
APIs is unsupported. The existing `crypto.min` API is unchanged.

| Function | Result / contract |
| --- | --- |
| `new(): State` | New empty hasher; initialization failure stops the program. |
| `update(state, input: Bytes): Boolean` | Append the entire borrowed input. |
| `updateRange(state, input: Bytes, offset: Integer, length: Integer): Boolean` | Append a checked subrange without allocating a slice. |
| `updateAddress(state, address: Integer, length: Integer): Boolean` | Append caller-owned raw memory without an input copy. |
| `finalize(state): Bytes` | Fresh 32-byte digest; does not consume or mutate the state. |
| `clone(state): State` | Independent context, including the buffered partial block and count. |
| `bytesHashed(state): Integer` | Total accepted input bytes; snapshots do not change it. |
| `digest(input: Bytes): Bytes` | One-shot digest. |
| `digestAddress(address: Integer, length: Integer): Bytes` | One-shot raw digest; invalid numeric ranges return empty Bytes. |
| `hex(input: Bytes): Text` | Lowercase hexadecimal encoding. |

Ordinary record assignment shares a State. Use `clone` to branch. A State's
`context` and `count` fields are implementation details: callers must not
construct or modify them. Context storage belongs to an automatically reclaimed
Bytes value, with no numeric handles, global state, TLS cache, or explicit close.
One thread may use a State at a time; distinct states do not share mutable
context storage. Returned digest mutation and source mutation after an update
cannot affect the state. A snapshot can be followed by more updates.

Updates reject negative lengths/offsets, invalid Bytes ranges and cumulative
counts above `2^61 - 1` bytes. The cumulative guard uses `length > maximum -
count`, before input reads or state mutation. Rejection leaves both count and
hash unchanged. Empty input, a range at the Bytes end, and raw `(0, 0)` are valid.
Raw addresses must be nonnegative and the last input byte must be at most
`2^63 - 1`; nonempty null ranges are invalid. These checks do not establish
memory ownership or readability. Raw callers must keep the complete input
range readable and stable until the call returns. Final bit-count words use
unsigned shifts instead of signed `count * 8`, including when bit 63 is set.

## Explicit custom link

Custom links must supply the SHA object and `libcrypto` independently. There is
no dependency on securecrypto, Monocypher, libssl, or protocol libraries. Run
from the repository root with a previously built compiler/runtime:

```sh
./build/minyarc example.min example.ll --library ./library
clang -O2 $(pkg-config --cflags libcrypto) \
  -c runtime/native/sha256.c -o build/sha256-native.o
clang -O2 -Wno-override-module example.ll build/minyar-default-runtime.o \
  build/sha256-native.o $(pkg-config --libs libcrypto) -lm -o example
```

On Windows omit `-lm`. Select matching OpenSSL headers and libraries from the
same toolchain/prefix (for example the chosen MSYS2 UCRT64 or CLANG64 prefix).
The normal launcher's native-package discovery/driver integration is supplied
by the parent workstream. The tests deliberately compile/link the independent
SHA object directly, without that driver discovery.

## Validation and provider decision

```sh
python3 tests/sha256.py --cases 1024
python3 tests/sha256.py --cases 1024 --sanitize
python3 tests/sha256.py --module sha256pure --cases 512 --sanitize
```

The test harness honors `MINYAR_TEST_COMPILER`, `MINYAR_TEST_RUNTIME`,
`MINYAR_TEST_CLANG`, `MINYAR_TEST_LINK_FLAGS` and `MINYAR_TEST_TIMEOUT`. It never
builds the compiler. `--sanitize` annotates every generated LLVM function via
`tests/llvm_sanitizer.py` and compiles a private ASan/UBSan runtime and native
objects. Generated LLVM receives ASan; UBSan covers the C sources. System
libcrypto itself is the distribution's uninstrumented library. The protected
page tests also run against that library. Leak detection defaults off because
the standard runtime retains its process-lifetime allocation machinery.

There are 2,840 deterministic cases covering every snapshot prefix of the
boundary lengths through 1,024 bytes, plus the requested seeded random cases.
Tests include the original standard/million-a vectors, three update paths,
empty splits, independent cloned tails/continuations, mutated returned digests,
continuation after snapshots, malformed and exhausted ranges, all 64 address
alignments over lengths 0–257, and 519 protected-page inputs. Synthetic counter
seeding tests the cumulative guard and maximum-length finalization without
claiming to hash exabytes.

An optimized pure Minyar candidate using machine raw reads is retained in
`tests/sha256pure.min`, derived from the read-only neo-vm implementation.
The final matched benchmark includes construction, update, snapshot/clone,
nonconsuming finalization, digest consumption and disposal. It compares actual
Minyar execution with OpenSSL EVP default dispatch, direct OpenSSL SHA default
dispatch, OpenSSL with x86 capability bits disabled (still an assembly library),
and unmodified Mbed TLS 3.6.5 portable C with only `MBEDTLS_SHA256_C` enabled.
The portable C comparator is separate from disabled-capability OpenSSL.

On the owned Boat's AMD Ryzen 9 9950X x86-64 environment, five rotating samples
of 64 operations over 1 MiB measured pure/EVP ratios of **8.47× one-shot** and
**8.44× snapshot/clone lifecycle**. Pure/portable-C ratios were **1.82×/1.89×**.
Both exceed the 1.5× pure preference. The selected native provider measured
**1.00×/0.96× EVP** and **0.99×/0.99× direct SHA**. At 64 bytes, its owned-value
wrapper overhead costs **3.84×/2.65× direct stack-context C**, although it remains
below EVP time; at 1,024 bytes those direct-SHA ratios are **1.28×/1.44×**.
These results justify the provider choice for image hashing; they are not a
claim of zero wrapper overhead for small inputs.

Exact commands, source/toolchain/provider hashes, sample variance and raw
results are retained in [the SHA evidence directory](evidence/sha256/README.md).
No merge, public driver integration, or Windows qualification is claimed here.
