# WS1: safe shared-memory threads — design decision

Research draft, 2026-10-12. Source baseline: Minyar `bf9c0e9`; parent selector inspected at `c38057c`. **This proposes a release boundary, not an implemented or proven threading system.** Implementation and Boat verification remain held pending `PHASE1_DONE`. No runtime changes or tests accompany this draft.

## Required release decision

WS1 is complete only with **actual concurrent sharing of managed immutable values**, atomic ownership of their cross-thread backing/control blocks, compiler-enforced Send-like boundaries, exclusive zero-copy buffer transfer, independent per-thread collectors, and kernel-blocking threads. Copied or exclusively moved messages between isolated domains are an implementation stage, not the shipping end state. At minimum, one FrozenBytes allocation must be retained and read simultaneously through handles in multiple domains, outlive its creator, and be reclaimed exactly once after the last share drops. That shared representation must be available to checked Minyar code, not just native channel internals.

Opt in to managed **OS threads**, each owning its runtime state and collector. Keep ordinary Bytes, Text, Lists, records, callbacks and their RC non-atomic and local. Admit cross-thread values only through checked runtime wrappers:

1. **Required to ship — `FrozenBytes`:** an immutable byte payload with a separate atomic owner; each thread has its own local managed handle shell. It exposes no mutable Bytes view, raw address or forgeable integer identity. This is actual simultaneous sharing of managed immutable backing, not a copied-message substitute.
2. Explicit Bytes transfer: detach the buffer from the sender's local Bytes object, replace that object's storage with a valid empty buffer, and attach the original buffer to a newly allocated receiver-local Bytes shell. **Every sender alias to the original shell observes empty Bytes.** The shell itself never crosses threads. This is a destructive buffer operation, not affine transfer of an arbitrary language value.
3. Bounded channels and typed thread/join handles; synchronization and lifetime ownership live in native control blocks. Start with named entry functions, scalar control data, and the two buffer operations above.

Use `MINYAR_THREADED` / `MINYAR_THREAD_LOCAL` from the parent's selector. `c38057c` rejects compiler arenas, fixed pools and lazy pools, permitting system/eager allocation; the selector alone does not move globals into TLS or make native libraries safe. Preserve the ordinary runtime/header ABI and its zero-atomic RC path. Thread support must not be advertised before the compiler checks, native audit and collector isolation are complete.

Independent preparatory review found that `c38057c` treats a zero-valued selector as enabled and misses an implicit pool selected by bounded RC without the system heap. That commit is unapproved and must not be integrated as a usable profile guard. After the implementation hold lifts, normalize absent/`0` to ordinary and `1` to threaded, reject invalid values, and validate the effective allocator including explicit bounded-RC configurations. Keep genuine eager malloc/free distinguishable from an implicit pool. Verify the configuration matrix in both ordinary and cycle engines before admission.

General `Unique<T>`, recursively frozen record/List graphs, actors and generic shared mutable containers are later extensions. FrozenBytes is the first concrete shared managed immutable value; its shared payload/control lifetime is real even though each access shell is domain local. Atomic counts are for explicitly cross-thread owners, not every allocation merely because the binary uses threads. The proposal in [concurrency-neodb.md](concurrency-neodb.md) keeps database execution state local to its shard while allowing shared immutable snapshots/buffers.

## What the primary sources support

These mechanisms inform the recommendation; none proves Minyar sound.

- **Swift:** [Swift Atomics](https://www.swift.org/blog/swift-atomics/) distinguishes atomic storage from ordinary accesses and adopts a C/C++ style memory model. [SE-0302](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0302-concurrent-value-and-concurrent-closures.md) checks sendability recursively and checks closure captures. [SE-0306](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0306-actors.md) isolates actor state but allows interleaving at suspension points. Lesson: lifetime atomics, boundary type checks and mutation isolation are separate; an actor is not a multi-step transaction.
- **Rust:** [Rc](https://doc.rust-lang.org/std/rc/index.html) is local, while [Arc](https://doc.rust-lang.org/std/sync/struct.Arc.html#thread-safety) synchronizes ownership without making its payload thread-safe. [Send/Sync](https://doc.rust-lang.org/nomicon/send-and-sync.html) distinguish moving ownership from access through shared references; Rc, unguarded interior mutation and raw pointers prevent automatic derivation. Lesson: do not derive sendability from “has an atomic count” or “has no explicit mutation in this function.”
- **Python:** [PEP 703](https://peps.python.org/pep-0703/#biased-reference-counting) splits owner-local and foreign shared counts. The shared count may be negative; queued merging, owner termination and merged states govern reclamation. Its implementation caveat also requires relaxed atomic accesses to owner/local fields to avoid C data races. The PEP separately coordinates container locking and cycle collection, including stop-the-world phases. Lesson: adding a plain owner id and two counters is not a safe implementation. Minyar can initially avoid this compatibility machinery by forbidding arbitrary heap sharing; defer biased counting until measured shared-buffer contention justifies it.
- **Pony:** [capabilities](https://tutorial.ponylang.io/reference-capabilities/reference-capabilities.html) separate isolated mutable `iso`, globally immutable `val`, local mutable `ref`, and a merely read-only `box`. [Orca](https://www.ponylang.io/media/papers/orca_gc_and_type_system_co-design_for_actor_languages.pdf), §§3–4, couples the type system to actor-local tracing and a message/reference protocol for shared objects. Lesson: a read-only alias is weaker than deep immutability, and local collection with shared values needs an explicit lifetime protocol; do not copy the collector without its capability assumptions.
- **Erlang:** [ERTS GC](https://www.erlang.org/doc/apps/erts/garbagecollection.html) gives each process its own heap/stack and collector. [Message transfer](https://www.erlang.org/doc/system/eff_guide_processes.html#sending-messages) copies ordinary terms, with same-node exceptions for reference-counted binaries and literals. Lesson: isolation plus a special immutable byte representation is a practical boundary; process isolation is a stronger fault boundary than threads.
- **Nim:** [memory management](https://nim-lang.org/docs/mm.html) distinguishes ARC/ORC's shared allocation heap and non-atomic counts, moved subgraphs, separate atomic ARC, and RefC's thread-local heaps. [Isolated](https://nim-lang.org/docs/isolation.html) is experimental, move-only and compiler checked. Lesson: shared allocation does not authorize concurrent mutation/count updates. Minyar's snapshot collector is not Nim's trial-deletion ORC, and needs its own transfer proof.

## Baseline architecture and consequences

Repository-relative links below target the intended `docs/` destination. Inspection used the frozen source, not only older research descriptions.

- [Architecture](architecture.md): the self-hosted [compiler](../compiler/compiler.min) combines parsing, checking, ownership and LLVM emission; the optional frontend adapts that core for closures/cycles/Result. New boundary checks must survive module resolution, interface caching, both frontends, native declaration validation and producer lowering.
- [RC](../runtime/minyar_rc.h) and its [cycle variant](../runtime/minyar_cycle_rc.h): an eight-byte `RcObject.ownership` packs non-atomic count/kind; frames, frame caches and pending work are static state. Compiler-owned producer tokens avoid retain/drop pairs; **they do not prove heap uniqueness**. Synchronous borrowed parameters can have live aliases outside the callee.
- [Bounded RC](../runtime/minyar_bounded_rc.h), [cycle registry](../runtime/minyar_cycles.h) and [collector](../runtime/minyar_cycles_collect.h): retirement queues, cohorts, root/gray pins, cursors and proofs assume one mutator. [Managed graphs](managed-graphs.md) adds selective tracing and 32 bytes of metadata without making graphs shareable. Moving a root without removing its queued/collector ownership can free or mutate live data on another thread.
- [Text/runtime](../runtime/minyar_runtime.c): stack depth/bounds and Text caches are global. `character_length` / `character_offsets` are lazily written, including on Unicode literals; backing Text owns slice storage. A language-level immutable Text is not transitively immutable runtime storage. Current Bytes uses the Text-shaped **local** shell; `Bytes.slice` and `Text(Bytes)` copy, rather than exposing shared mutable buffer views. Future views would require reopening this proof.
- [Callbacks](../runtime/minyar_callbacks.h) already use process-lifetime unique domain ids and reject foreign-domain calls; [closure lowering](../compiler/closure-compiler.min) records capture edges. That small atomic domain allocator does not isolate RC/stack state. Do not remove the callback check to make thread entry work.
- `finishParallelFunction` / `checkParallelCalls` deliberately exclude managed values and ordinary runtime calls from the scalar `parallel function` ABI. Add a distinct checked managed entry path; leave this ABI intact.
- [Native ABI](../runtime/minyar_native.h) borrows Text/Bytes pointers and returns owned runtime values. All native declarations are a trusted boundary. [Files](../runtime/native/files.c) already has kernel-blocking syncer threads that avoid managed values; its registry/lifecycle still assume managed calls come from one thread. [Net](../runtime/native/net.c) already has TLS error state at this baseline: do not use the older research claim that its error buffer is still global.

## Precise states and transitions

An execution domain is initially one fixed OS thread, identified by a non-reused runtime id. “Owner” means the party responsible for destruction, not permission to access memory through an arbitrary pointer.

### Initial release states

- **Local(D):** the Bytes shell and all aliases belong to D. Shell/data RC and collector bookkeeping are accessed only by D. Ordinary local containers may retain that shell. No foreign root may name it.
- **Detached(Q):** a native queue envelope exclusively owns the former backing allocation, its initialized length, capacity, allocator provenance and cleanup obligation. No managed shell, borrow or cache can still name that allocation. Nobody mutates its payload while queued. Q owns it even if the sender exits. The sender shell remains Local(D) but contains independent empty storage.
- **Local(E) after receive:** E allocates/registers a new local shell and adopts the envelope's buffer. It owns all resulting local aliases; the envelope is consumed once. The sender shell stays empty and may be reused independently. The payload pointer is preserved; payload RC need not become atomic because it is never concurrently owned/accessed by both domains.
- **SharedFrozen:** a native control block owns immutable initialized bytes and an `_Atomic` strong count. Each local handle shell and each queued message owns one strong share; same-thread aliases to one shell use its ordinary local RC. No writable alias or lazy metadata survives publication. Releasing the last strong share frees only native storage, never a foreign thread's local shell or collector node. No weak references in the initial API.

`transfer(bytes)` must reserve queue capacity and prepare the empty replacement/envelope **before detaching**. At the successful enqueue linearization point the queue becomes owner and all aliases to that shell become empty. Full/closed/invalid failures leave Bytes unchanged; no ambiguous “failed but consumed” result. Sender detach is single-threaded and cannot call user callbacks or re-enter Minyar. A reserved queue entry prevents a receiver from observing partial initialization. Receipt transfers exactly one obligation; close/drop of unread envelopes frees their detached raw allocations once.

`freezeCopy(bytes)` copies initialized bytes into fresh immutable cross-thread storage and leaves all sender aliases unchanged. A separate explicit `freezeTransfer(bytes)` uses the same alias-emptying detach protocol, then attaches that allocation to an atomic control block without copying the payload. This operation requires the allocation provenance/cleanup conversion below. Freezing is permanent: mutable local copies require an explicit copy; a count of one does not silently restore writable access.

Never publish the existing local Bytes shell, cast its plain count to an atomic count, or pass `MinyarText*` as a cross-thread handle. Cross-thread storage must have its atomic type and destructor installed before publication. Capacity/spare bytes remain inaccessible through FrozenBytes.

### Intended general model — not a first-release promise

**Unique(D,G)** means D has the sole external capability for a closed mutable graph G, not just a root with RC=1. Internal aliases/cycles may exist only inside G. There are no outside mutable references, callbacks, native borrows, collector pins, retirement owners or stack temporaries into G; outward references may target separately owned SharedFrozen values. A future affine checker must make the unique capability uncopyable, consume it on send, reject uses on every control-flow path, and keep interior borrows lexical/non-escaping.

Proposed eventual transitions are `Local(D) -> Unique(D,G)` only with a whole-graph isolation proof, `Unique(D,G) -> InFlight(Q,G) -> Unique(E,G)` with exclusive collector/allocator migration, and `Unique(D,G) -> SharedFrozen(G)` only after removing every mutation path. Returning Unique to unrestricted Local loses the ability to transfer it again without a fresh proof. SharedFrozen never points to Local data; Local/Unique may own shares of SharedFrozen. Cycles spanning domains and arbitrary SharedMutable graphs are excluded. A future locked cell requires checked guard lifetimes and a no-reference-escape rule, not merely a mutex field.

The first-release alias-emptying Bytes operation meets a narrower exclusive **allocation** transfer invariant without a general `Unique<T>` checker. It must not be described as proof of graph transfer or implicit move semantics.

## Compiler boundary checks (“Send-like”)

Use a closed set of built-in boundary kinds first; reject unknown types. “May move to another domain” and “may read concurrently” are different properties.

- Scalars can be copied. FrozenBytes and typed channel/control handles may be transferred because their native payload/control ownership is synchronized. Ordinary Bytes may only cross via detach; never by a normal argument/return. Text, List, record, Result containing local references and ordinary Callback are local unless a later rule explicitly proves otherwise. Even scalar-only records currently have reference semantics and are not automatically Send.
- Validate spawn input, entry arguments/results, channel messages and join results, including their real representation. Rebuild each managed wrapper shell in the receiving domain; checking a type name then copying a local wrapper pointer is unsafe. Result active payloads and future aggregates need recursive checking.
- Start with a **named** entry function and explicit accepted arguments. No closure spawn in the first release. Later Send closures must validate every captured environment edge and reject captured local aliases, mutable by-reference captures and callback-domain assumptions; capturing an Integer handle does not make its resource safe.
- Thread-local helper functions may create/use local Text, records and local callbacks after runtime isolation. Track reachable native/library effects; reject unreviewed native code, UI/main-thread APIs and helpers using unsynchronized process globals. Interface metadata must retain these effects across imports and fail closed for stale/unknown interfaces. Merely allowing a root function does not check its callees.
- Check **main/top-level and sender-side effects as well as worker effects** in a safe threaded executable. A sender can retain `machine.address(bytes)` before an otherwise valid detach; worker-only checks miss this escape. Reject address/load/store/jump/indirect-entry operations and unknown native effects throughout the reachable graph. Record resolved semantic call edges and exact native symbol/signature contracts, not emitted-LLVM substring matches or package-name approval. Incremental cache reuse needs persisted effects and policy/schema invalidation; force complete checking until that exists. Ordinary indirect callbacks are rejected initially; later local callback support needs body/capture effect checking, not just a matching domain id.
- No user-written `Send` assertion, integer-to-pointer cast or arbitrary `native` escape participates in the safe proof. Existing native/`machine` escape hatches remain trusted/unsafe and need explicit provenance. A safe API must not expose raw addresses as Integers.
- Thread-safe endpoint operations do not authorize concurrent access to the same local endpoint shell. Passing an endpoint creates a fresh receiver-local shell owning the native control block.

This is feasible as a few recognized boundary types/operations in the optional frontend and native runtime, before adding user-defined trait derivation or a full capability lattice. It is additional checking work; the baseline compiler does not implement it.

## Lifetime, atomics and allocator accounting

For SharedFrozen, clone a strong share only from an already owned live share. Begin with conservative acquire/release operations; a reviewed optimization can use [relaxed increments](https://doc.rust-lang.org/nomicon/arc-mutex/arc-clone.html) and [release decrement + acquire on the final release](https://doc.rust-lang.org/nomicon/arc-mutex/arc-drop.html). Bound counts and detect overflow before wrap. An atomic count load is not permission to retain a possibly freed pointer. Exclude weak upgrades and atomic raw-pointer replacement initially.

Queue publication uses mutex unlock/lock synchronization (or a separately reviewed release/acquire algorithm); the RC counter does not publish payload bytes. Prefer a bounded mutex/condition-variable queue before lock-free structures. Synchronize closure, capacity, cancellation and queue ownership under the same control protocol. Signal a readiness source only after enqueue; consumers drain/recheck under the lock to avoid lost wakes. No queue lock is held across user code, a kernel wait, collector work or a destructor that might acquire another lock.

System/eager backing is necessary but not sufficient for detaching ordinary buffers: allocation data has an `RcData` size prefix and local accounting. Transfer must remove the exact data charge from D, hold it as channel/shared storage in transit, and adopt it into E's ledger on receipt. Queue cancellation/free and SharedFrozen last release use a native allocator-aware free path that does not decrement the current thread's unrelated RC ledger. Preserve the prefix/provenance or use dedicated transferable allocations; do not call `free(payload)` on an interior pointer. Shell charges stay with their own domains. Process totals include queued capacity, spare buffer capacity, shared blocks and native controls.

Header/refcount type changes, mixed plain/atomic accesses and mutable lazy initialization cannot occur while published. Do not make ordinary local retain/release dynamically test “am I shared?” on every operation. Thread-control/channel reference counts and synchronization atomics are separate from payload RC; local object counts remain plain.

## Per-thread runtime and blocking behavior

Before managed thread entry, isolate **all** ownership frames/free frames, bounded object/frame/chunk queues, heap ledgers, stack guard depth/bounds, cycle registry/cohorts/gray queues/pins/proofs, runtime caches and mutable error state. Use the selector for TLS in the opt-in profile and explicit init/drain/destruction at thread boundaries. Coordinate stack-guard storage with WS2; no runtime edit is part of this draft. Audit native registries separately rather than converting every process global into unrelated TLS state.

Text literals are particularly subtle: one emitted literal can be read on several threads even when no Text argument crosses the boundary. Threaded literal access must yield a domain-local shell over immutable literal bytes, with local lazy indexes/backing, or use a separately proved fully immutable indexed representation. **Preindexing alone is insufficient:** existing Unicode access can update recent-position cursors even after `character_offsets` exists. A shared representation must eliminate those writes or place all cursor state in domain-local storage. Making an integer cache TLS does not fix shared literal shells. Future FrozenText requires freezing the entire backing graph, completing indexes before publication and removing every mutable cursor path; defer it.

For the required release, copy literal payloads into ordinary domain-owned storage when creating their local Text shells. The existing destructor frees an owning Text's data through its `RcData` prefix, and unique-owner Text operations may reallocate that data; merely pointing a fresh ordinary shell at static literal bytes is invalid. Any later zero-copy static backing needs explicit immutable provenance plus compatible destructor and growth rules, separately reviewed. Qualify Unicode first use, concatenation/growth, slices and domain teardown with exact accounting and sanitizers.

Each domain runs its own existing bounded collector/service points and owns its traced roots. SharedFrozen is an opaque leaf with a strong share, never a foreign traced node. No collector scans another thread's mutable graph. Ordinary local cycles stay local; general graph transfer is rejected until cohort/gray pins and pending retirement can be migrated safely. Thread exit drains local cleanup and releases its own shared/control shares; it cannot discard messages or buffers still owned by queues/other threads. Do not publish thread completion before its promised cleanup is complete.

Use one native OS thread per explicit spawned worker, typically a bounded application worker/shard pool. Channel receive, join, file I/O and sleep **block that kernel thread**; other domains keep running and collecting. No fibers, cooperative scheduler or async cancellation promise. Event loops use nonblocking try-send/try-receive plus channel readiness; never block their owner waiting for CPU work or fsync. Service local collector debt before long waits and at deadlines while debt remains; otherwise pending local cycles can be stranded forever on an idle blocked thread. Keep the existing work-unit budget and avoid spinning on live cycle graphs.

Stop is cooperative: close a channel, wake waiters, let entry return, then join. Do not terminate a thread holding locks/native borrows. Define self-join, double join, close during wait and start failure as recoverable control errors. Existing `fail`, arithmetic/bounds stops and `exit` are process fatal; threads do not supply per-query fault containment. Blocking fd operations need ownership/duplication rules so close/reuse cannot change an in-flight job's resource.

## Threat model and unresolved release gates

Target ordinary checked Minyar programs with arbitrary scheduling, repeated aliasing, untrusted message contents, bounded resource pressure and channel/thread closure. Prevent data races, premature/double destruction, stale-handle reuse, access through transferred aliases, uninitialized-byte disclosure and wrong-domain callback/collector entry. Trusted compiler/runtime/native code, OS primitives and allocator are in the trusted base. This is not a sandbox for native code or a remedy for application deadlock, starvation or transactional races.

Required proofs/checks still outstanding:

1. **Detach:** enumerate every Bytes alias/view/borrow path, including native retaining pointers and compiler-cached addresses. A safe native call must finish its borrow before detach; asynchronous native users must copy or retain an explicit shared owner. Test aliases in locals, records, Lists and callbacks; sender reuse must not affect receipt.
2. **Literal/TLS audit:** map every runtime and native static, including emitted Text literals and shared callback/domain state. Reject packages not audited for thread entry; generation tokens do not by themselves synchronize registries.
3. **Accounting/destruction:** detached data prefix, capacity and ledgers survive send/receive/close/thread-exit interleavings without invoking foreign-domain RC. Queued envelopes hold native ownership independent of sender lifetime.
4. **Compiler enforcement:** wrapper opacity, transitive entry/native effects, imported metadata, bootstrap/frontend routing, lowering of temporaries and results; negative cross-domain cases must be hard errors. Scalar ABI changes are not a substitute.
5. **Collector/exit progress:** two domains with independent cycle debt, blocked receivers, unread packets, stale callback ids, join/close races. General graph transfer stays rejected.
6. **Qualification and integration — all required:** Linux/macOS/Windows OS-thread/condition/readiness contracts; TSan over the threaded runtime and generated managed code, appropriate other sanitizers and exact-ledger/schedule-controlled lifetime checks; the literal requested **±1% single-thread performance gate** with paired frozen-base comparisons for compiler self-compile, Minyarcraft, Atacama, JSON and neo-db statement workloads; **8-vCPU scaling using actual shared managed immutable inputs** retained/read concurrently by workers, with correct results and reported throughput/CPU/memory rather than scalar-only or copied-input substitutes; fresh independent review and **integrator merge into `v2`**, full platform suites and CI. Existing thresholds must not be loosened. Boat work remains held until `PHASE1_DONE`, and only the integrator merges/pushes. These are release gates, not executed evidence; the parent owns the detailed qualification plan.

Suggested first concrete API (names/signatures are proposals, not accepted Minyar syntax): `threads.spawn(namedEntry, frozenInput)`, `threads.join(thread) -> IntegerResult`; `channels.byteChannel(capacityBytes, capacityMessages)`; `tryTransfer(sender, localBytes) -> IntegerResult`; `tryReceiveBytes(receiver) -> BytesResult`; `freezeCopy`, `freezeTransfer`; `trySendFrozen`, `tryReceiveFrozen`; `notifySocket` and `close`. Channel endpoints and FrozenBytes must be opaque checked types. Define empty success, empty queue, closed queue and error distinctly. `tryTransfer` is the explicit alias-emptying operation above. Initially keep entry results scalar and message schemas byte encoded; add typed record messages only after recursive boundary checking exists. A new checked thread-entry declaration is required; do not route this through the current scalar `parallelEntry` address API.

Implement later in small reviewed chunks: per-domain runtime/literals and profile guard; checked entry plus bounded native channels; alias-safe detach with exact accounting; immutable atomic FrozenBytes with actual simultaneous sharing; then application sharding. Treat the isolated-domain channel stages as milestones. Do not mark WS1 complete or advertise safe shared-memory support without the full objective above and qualification evidence. Nothing here closes neo-db G3/G13 or claims the larger Unique/actor model is implemented.
