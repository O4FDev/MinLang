# Client handshake PTO review

The transport now keeps an absolute client handshake alarm when no Initial or Handshake packet is in flight and no Handshake acknowledgement has established peer address validation. It probes Handshake when those keys exist, otherwise an Initial datagram padded to at least 1200 bytes. Application PTO starts after handshake confirmation. The design follows [RFC 9002 sections 6.2.1–6.2.2.1](https://www.rfc-editor.org/rfc/rfc9002.html#section-6.2.1) and [key disposal](https://www.rfc-editor.org/rfc/rfc9002.html#section-6.4).

Two scalar Connection fields distinguish actual Handshake ACK evidence from the client's local amplification exemption and retain the absolute no-flight deadline. Idle polling, duplicate ACKs and early application ACKs preserve that deadline. Genuine handshake progress, key disposal and Retry reset it. Closing, draining, version negotiation failure and release clear it.

A timeout selects one earliest eligible packet space, advances shared backoff once and refreshes other scheduled spaces. A late poll consumes already-expired unselected deadlines as well. ACK refresh respects deliberately disarmed unrelated timers, while actual send, migration and key transitions can rearm them. The generic congestion helper's counter reset is restored for clients lacking peer-validation evidence; Initial and early-data acknowledgements therefore preserve backoff.

The sender promotes existing queued CRYPTO when possible and otherwise retransmits reliable content or emits PING. Existing packet-size, path, amplification, history-admission, pacing and probe bounds remain in force. No timer queue or application payload retention was added.

The twelve virtual-clock modes in [quic-pto.min](../../tests/quic-pto.min) exercise actual TLS handshakes, authenticated peer packets, no-flight Initial/Handshake probes, duplicate timing, real ACK/backoff, confirmed application recovery, Retry, key disposal, closing and draining. Shared-space cases provide amplification credit using three genuine Initial datagrams and keep the server unvalidated. Application-ACK cases use genuine resumed traffic keys and three actual Initial PTOs, then three blocked Handshake PTOs. Their 8192-entry admission obstruction repeats references to an actual unresolved Sent record; it is a controlled admission-state adversary, not 8192 distinct network packets.

The original Finished probe fixture now reads its deadline from quic.nextTimer rather than from the forbidden preconfirmation application timer. All deadline bounds, Handshake transmission, establishment and cleanup assertions remain. Other existing transport, retained-history, RTT and persistent-loss fixtures were unchanged.

Retained runtime reds include missing alarm41, premature application51, blocked expiry83, Initial backoff47, application deadline53, key-discard48/58 and shared expiry66 at both optimization levels. An intermediate O0 run also independently exposed application-backoff54. The unchanged broader suite also caught setup98 when an unrelated application ACK revived the retained-history fixture's deliberately disabled Handshake timer. Fixture setup55 and a subsequent admission-witness false53 were preserved separately and are excluded from product defect counts. A one-line expired-timer mutant became harmless after redundant shared refresh; the final semantic mutant removes all paths that consume that original deadline.

Final frozen-source verification passed twelve modes at O0 and O2, and at O1 with ASan/UBSan/LSan. Fourteen semantic mutants failed at exact expected runtime assertions at both optimization levels (28 kills), with successful compilation. The unchanged full QUIC suite passed native in 41.49 seconds and sanitized in 96.96 seconds. Source hashes matched before and after every final profile. Work ran sequentially on the existing Boat host with the 75% resource guard; no local builds, infrastructure or spending occurred.

The [driver](../../tests/quic-pto.py) retains compiler/runtime status, raw subprocess output, flags, binary hashes, source and fixture hashes. Replays use fresh artifact destinations:
- python3 tests/quic-pto.py --optimization 0 --artifacts NEW_DIRECTORY
- python3 tests/quic-pto.py --optimization 2 --artifacts NEW_DIRECTORY
- python3 tests/quic-pto.py --optimization 1 --sanitize --artifacts NEW_DIRECTORY

This is a client-handshake PTO slice. Server anti-amplification timer suppression, comprehensive loss-timer precedence, PADDING accounting and general RFC conformance are outside the claim. Handshake ACK evidence relies on the current sender using every packet number below next; future intentional packet-number gaps need explicit sent-packet evidence. No new official interoperability, long soak, Windows/macOS, performance or production-readiness claim is made. Compiler and runtime sources remain byte-identical to the base; no ordinary compiled-object or timing inference is made from that fact.
