# Cycle cleanup and reactor progress

The opt-in snapshot collector was advancing, but an idle reactor could still use almost one CPU. Taking and dropping a temporary external owner of a live interior node requests another cycle epoch. The reactor's own helper calls can repeat that operation on every empty readiness batch. Waiting for *all* pending cycle work to disappear therefore need not terminate, even when every captured cohort finishes.

The independent regression uses 32 records with self and ring edges, keeps one external root, and repeatedly borrows and releases an interior node without changing any owning slots. With the original Boolean service policy, budget 1 completed 19 epochs in 1,552 iterations and still never permitted a wait. This was a runtime assertion failure, rather than a compilation failure. The earlier real edge experiment reported idle CPU above 90%; verification of that application with this change belongs to the edge owner.

The initial correction recorded completed finite cohorts and allowed a wait only when one finished. That passed the independent 32-node fixture and the real 32-gateway test (1.66% of one CPU). The real 2,048 authenticated, H2 PING-verified gateway test contradicted its scale conclusion: idle CPU was 20.7594%. Large finite cohorts required many immediate readiness polls before each permitted wait. The expanded independent test reproduces the defect with 2,048 live traced records and an assertion that a cycle-only batch midway through ROOTS/MARK must permit a bounded wait.

The private callback runtime wait policy now services exactly the existing batch budget and permits a wait of at most 10ms whenever the sole remaining job is cycle collection, including an unfinished captured cohort. Ordinary object, frame and temporary-chunk debt continues to request an immediate readiness poll. The cycle request and active cursors remain queued. An infinite caller timeout also receives the 10ms wake deadline, so the loop resumes collection without requiring network activity. A shorter or zero caller timeout stays shorter or zero. With no debt, the caller's timeout passes through unchanged; invalid timeouts still reach the existing event-loop validation.

This deliberately exchanges idle cohort completion latency for reactor fairness. A loop with no other runtime service points advances one existing batch per wake; shorter waits, network readiness and ordinary program service points can advance it sooner. With a fixed graph, the number of collector units remains finite. The regression reports both the batches needed to reclaim an unreachable two-node cycle during continued borrows of a separate live graph and the sum of the returned wake deadlines. For example, the 4,096-node fixture at budget 32 initially needed 470 batches with at most 4.7 seconds of scheduled waiting; budget 1 needed 18,332 batches with at most 183.31 seconds. These are deadline sums from a deterministic progress test, not measured wall times or universal bounds for growing application graphs. No request is discarded to shorten that delay.

This changes scheduling, rather than reachability. Root shading, incoming counts, snapshot generations, gray pins, captured scan limits, registry unlinking and round-robin queue budgets are unchanged. Dropping the last temporary external owner must continue to request collection: that temporary can become the graph's only root after an earlier owner disappears. Suppressing those requests would silently retain real cycles. The regression exercises that transition and requires exact eventual recovery of every object and byte.

`tests/cycle-progress.py` runs the independent progress fixture on system, 1MiB fixed-pool and eager profiles. Bounded profiles cover budgets 1, 32 and 1024, both natively and under ASan/UBSan. Each profile runs 32, 2,048 and 4,096 live traced records. It checks own-process idle CPU against the existing 2% target, midcohort finite wake deadlines, invalid timeouts without service, ordinary and mixed cleanup debt, live-root retention, reclamation during ongoing borrowed churn, and last-temporary-root recovery. `--legacy-service` reproduces the original assertion using the old Boolean policy. The repository's existing independent graph/reachability oracle remains relevant for mutation and pinning safety.

The maintained compiler and ordinary runtime sources are unchanged. On the Boat Linux host, ordinary production runtime objects compiled before and after this change were byte-identical (SHA256 `effee3192380318446fa53efc9d223dfb98aa04a37bb0c236889bf1131ff306a`). This evidence does not establish Windows, macOS AppKit, full CI, or the application's long soak results. The edge owner reran 2,048 certificate-authenticated, H2 PING-verified gateways with the revised per-batch policy. Protocol work and cleanup passed, but idle CPU remained 8.9916% of one CPU, above the unchanged 2% gate. The independent runtime evidence therefore establishes the scheduling and reclamation contracts, not application-scale idle success. The remaining per-wake work is still under investigation by the edge owner.

## Surviving graph retracing

A subsequent native symbol-only profile of 2,048 authenticated gateways measured 89.57% of its idle samples in the collector unit, 4.29% in shading and 2.45% in bounded traced polling. Application work accounted for 0.61%. Per-batch pacing alone therefore did not remove the dominant work. The new independent fixture models a rooted connection list, callback records, capture environments and wider state records, with 256 generated-style service points while each read's temporary owners remain held. At 2,048 peers, the earlier collector spent 135,188 units in the measured 200-read interval; at 32 peers it completed 50 unnecessary cohorts.

The opt-in collector now records a reachability witness from one independently held external anchor. Conservative snapshot shading still decides which objects survive. Witness propagation is separate: only nodes reached along traced owning edges from that anchor receive a certificate. A temporary root or a conservative write barrier cannot certify an unrelated component. A node already scanned conservatively is queued at most once more when first reached from the anchor; each scan still visits at most one field per unit. The captured cohort and field limits remain finite.

Dropping the last read temporary continues to enqueue a cycle job and increment the bounded debt count. Its accounted unit can retire that request without tracing if the candidate has a current certificate, the anchor is still externally held, and no traced owning edge has changed. Other requests perform the normal snapshot collection. The stable 200-read interval then needs 200 units and no new cohorts in the independent fixture. This shortcut applies to the one certified component; other components may still require ordinary tracing.

Every traced owning-edge addition or removal invalidates the witness before changing the incoming count or publishing a new slot. Scalar writes do not invalidate it. Losing the anchor's last external count invalidates it too, and later selection skips that failed temporary anchor. Unregister clears anchor pointers before an allocator can recycle their storage. Collector-internal removal of unreachable white edges does not invalidate the surviving anchor's path. Nullable values, untraced containers and retired stack/local owners retain their existing count rules and callback domains retain their entry checks.

Two low alignment bits in the existing gray link hold a certificate and its generation. Metadata stays 32 bytes; compile-time alignment checks and registration-time checks protect the tagged link. Registration clears tags. A bounded SWEEP visit removes old-generation tags before a second generation flip could confuse them with a different anchor. This handles invalidation during ROOTS, conservatively marked nodes, disconnected new roots and address reuse without reading a retired anchor.

The independent witness regression checks exact debt at the last-temporary drop, bounded work, both inactive and surviving components, ownership transferred into a traced list, loss of the original root while a read temporary becomes the only root, owning replacements split at service points, mid-ROOTS invalidation, generation reuse and an anchor with no incoming edge. The latter must clear its proof before its deferred destructor can free it. System and 1MiB fixed-pool profiles cover budgets 1, 32 and 1024; eager collection retains its existing 32-unit service. The earlier progress tests retain their assertions: their deliberate midcohort test now starts with an actual owning replacement so a legitimate new snapshot is required.

This adds a reachability proof shortcut rather than a new wait allowance. Existing mixed-debt immediacy, the 10ms cycle-only deadline, queue budgets and the 2% idle target stay unchanged. The independent runtime checks cannot establish application-scale idle success; that requires the edge owner's source-current 2,048-gateway retest.

The source-frozen Boat verification passed 14 native and 14 ASan/UBSan witness cases, the existing 21 native and 21 sanitized progress cases, the 160-case independent graph oracle and six native/sanitized callback-domain cases. Seven isolated wrong implementations were killed by exact runtime assertions at O0, O2 and ASan/UBSan, with budgets 1 and 32: missing addition/removal invalidation, a witness covering the wrong component, an old generation accepted for a new anchor, omitted old-tag clearing, an unregistered anchor pointer left live, and renewed full scans for stable reads. A zero-count gray anchor is pinned only until its captured scan finishes and still reaches exact zero objects, bytes and queued debt. The ordinary production runtime object remains byte-identical with the SHA256 recorded above. These Linux results preserve the original host/CI limitations.
