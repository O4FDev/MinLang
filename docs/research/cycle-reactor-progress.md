# Cycle cleanup and reactor progress

The opt-in snapshot collector was advancing, but an idle reactor could still use almost one CPU. Taking and dropping a temporary external owner of a live interior node requests another cycle epoch. The reactor's own helper calls can repeat that operation on every empty readiness batch. Waiting for *all* pending cycle work to disappear therefore need not terminate, even when every captured cohort finishes.

The independent regression uses 32 records with self and ring edges, keeps one external root, and repeatedly borrows and releases an interior node without changing any owning slots. With the original Boolean service policy, budget 1 completed 19 epochs in 1,552 iterations and still never permitted a wait. This was a runtime assertion failure, rather than a compilation failure. The earlier real edge experiment reported idle CPU above 90%; verification of that application with this change belongs to the edge owner.

The collector now records completed finite cohorts. The private callback runtime wait policy services exactly the existing batch budget. Ordinary object, frame and temporary-chunk debt continues to request an immediate readiness poll. Once a cohort has completed, the reactor may wait for at most 10ms when the only remaining debt is a new cycle request. That request remains queued. An infinite caller timeout also receives the 10ms wake deadline, so the loop resumes collection without requiring network activity. A shorter or zero caller timeout stays shorter or zero. With no debt, the caller's timeout passes through unchanged; invalid timeouts still reach the existing event-loop validation.

This changes scheduling, rather than reachability. Root shading, incoming counts, snapshot generations, gray pins, captured scan limits, registry unlinking and round-robin queue budgets are unchanged. Dropping the last temporary external owner must continue to request collection: that temporary can become the graph's only root after an earlier owner disappears. Suppressing those requests would silently retain real cycles. The regression exercises that transition and requires exact eventual recovery of every object and byte.

`tests/cycle-progress.py` runs the independent progress fixture on system, 1MiB fixed-pool and eager profiles. Bounded profiles cover budgets 1, 32 and 1024, both natively and under ASan/UBSan. It checks own-process idle CPU against the existing 2% target, finite wake deadlines, no-debt and invalid-timeout behavior, ordinary cleanup debt, live-root retention and last-temporary-root recovery. `--legacy-service` reproduces the original assertion using the old Boolean policy. The repository's existing independent graph/reachability oracle remains relevant for mutation and pinning safety.

The maintained compiler and ordinary runtime sources are unchanged. On the Boat Linux host, ordinary production runtime objects compiled before and after this change were byte-identical (SHA256 `effee3192380318446fa53efc9d223dfb98aa04a37bb0c236889bf1131ff306a`). This evidence does not establish Windows, macOS AppKit, full CI, or the application's long soak results.
