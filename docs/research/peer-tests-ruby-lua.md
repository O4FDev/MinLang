# Ruby and Lua testing audit for Minyar

Research retrieved 2026-10-04. Pinned official repository snapshots: Ruby `b61936bc29156f6abff617f381d968a25b1a8e79`, Lua `0b29f408433e92953cc72b1d3e06c7ac8139e439`. Both GitHub recursive trees were complete (`truncated: false`); Ruby contained 11,821 blob paths, Lua 111. This inventories major families and samples implementation and test bodies; it does not claim every individual test was read. Neither upstream suite was built or run. Source was available for both; Lua's repository includes `testes/` and internal `ltests.c`, so a separate release archive was unnecessary.

Local baseline was read for the [Python/Swift companion audit](peer-tests-python-swift.md): language guide, testing guide, Makefile, conformance/diagnostic/regression harnesses, with focused inspection of runtime-unit, adversarial and incremental-module tests. Minyar already tests O0/O2, sanitizers, deterministic fuzzing, exact diagnostics, reference ownership, fixed/lazy/system/eager modes, allocation bounds and compiler fixed points. Gaps below are relative to inspected fixtures; candidate research is not proof of bugs. Costs: S = half to two days; M = three to five days; L = over a week. Priorities P1/P2/P3 mean near-term/scheduled/defer.

## Ruby: inventory and inspected evidence

[Ruby source](https://github.com/ruby/ruby/tree/b61936bc29156f6abff617f381d968a25b1a8e79) has several intentionally distinct layers:

- `bootstraptest/`: small subprocess-based language/VM regressions supported by `bootstraptest/runner.rb`; useful when the normal runtime/test library is not reliable yet.
- `basictest/`: basic interpreter checks with its own runner.
- `test/`: core language/runtime (`test/ruby`), extensions, standard libraries, parser and tool tests; `tool/test/runner.rb` routes to Test::Unit support under `tool/lib/test`.
- `spec/ruby/`: behavior specs grouped as language, core, library, optional C API and command-line; `spec/mspec/` supplies MSpec. `spec/bundler` and other packaging specs are additional families, not language conformance.
- `bootstraptest/test_yjit.rb` and other JIT-related tests, `yjit/`, `zjit/`, Prism-related tests, GC tests and native extension fixtures cover implementation-specific behavior. Their existence was inventoried; JIT/Prism/native internals were not comprehensively reviewed.
- `benchmark/` is a separate performance family. [common.mk](https://github.com/ruby/ruby/blob/b61936bc29156f6abff617f381d968a25b1a8e79/common.mk) explicitly wires bootstrap/basic, test-all, test-spec, test-tool and other targets. A top-level test command does not imply every possible resource-heavy family runs.

Read/sampled [bootstrap runner](https://github.com/ruby/ruby/blob/b61936bc29156f6abff617f381d968a25b1a8e79/bootstraptest/runner.rb) (subprocesses, output, stress controls and timeouts), [flow cases](https://github.com/ruby/ruby/blob/b61936bc29156f6abff617f381d968a25b1a8e79/bootstraptest/test_flow.rb), [literal cases](https://github.com/ruby/ruby/blob/b61936bc29156f6abff617f381d968a25b1a8e79/bootstraptest/test_literal.rb), [Test::Unit entry point](https://github.com/ruby/ruby/blob/b61936bc29156f6abff617f381d968a25b1a8e79/tool/test/runner.rb), [pairwise generator](https://github.com/ruby/ruby/blob/b61936bc29156f6abff617f381d968a25b1a8e79/test/ruby/allpairs.rb), [array](https://github.com/ruby/ruby/blob/b61936bc29156f6abff617f381d968a25b1a8e79/test/ruby/test_array.rb), [string](https://github.com/ruby/ruby/blob/b61936bc29156f6abff617f381d968a25b1a8e79/test/ruby/test_string.rb), [integer](https://github.com/ruby/ruby/blob/b61936bc29156f6abff617f381d968a25b1a8e79/test/ruby/test_integer.rb), [parse](https://github.com/ruby/ruby/blob/b61936bc29156f6abff617f381d968a25b1a8e79/test/ruby/test_parse.rb) and [GC](https://github.com/ruby/ruby/blob/b61936bc29156f6abff617f381d968a25b1a8e79/test/ruby/test_gc.rb) regressions. The [Ruby Spec README](https://github.com/ruby/ruby/blob/b61936bc29156f6abff617f381d968a25b1a8e79/spec/ruby/README.md) describes cross-implementation behavioral specs and optional leak checks for descriptors, temporary files, threads, subprocesses and environment. This audit inspected that documented contract, not the entire MSpec leak-check implementation.

| Candidate and origin | Minyar translation and incremental gap | Priority / cost |

| Pairwise configuration coverage (`allpairs.rb`) | Produce a manifest over profile × cleanup budget × instrumentation × optimization × module-cache state × ownership mode. Assert every supported pair is represented, keep mandatory boundary/full matrices untouched. Existing stack ownership has 36 bounded configurations plus fallbacks; pairwise coverage is a way to audit cross-suite holes, not a reason to reduce those strong checks. | P1 / M |
| Stress reclamation on allocation (`test_gc.rb:test_gc_stress_on_obj_allocation`, `test_gc_stress_on_realloc`) | In a test-only runtime, service pending bounded cleanup at every eligible allocation or with a seeded adversarial cadence, then run alias/temporary cases. `tests/idle-service.c` already proves allocation/reallocation reset idle counters and service pending debt at the exact configured cap; budget=1 also stresses limited progress. The only proposed extension is combining existing legal service events with generated live-alias workloads and a logged schedule; do not claim allocation-triggered cleanup itself is missing. Respect legal scheduler entry points; Ruby compacting-GC/write-barrier mechanics are incompatible. | P2 / M |
| Overlapping shared backing (`test_array.rb:test_splice_shared_buffer_overlapping`) | Translate array shared-buffer scenarios to overlapping **Text** views: slice a root at different offsets, join the slices, release root/one view, verify remaining content and cleanup. Minyar Lists do not expose Ruby slicing/concat APIs. Existing runtime-unit tests check nested/full/tiny slices; delta is a systematic overlapping-view lifetime/order matrix. | P1 / S |
| Receiver mutation plus capacity transition (`test_array.rb` callback/reallocation regressions) | Build a List just below growth, evaluate an index/RHS helper that mutates its alias and forces growth, then verify order, retained receiver and original element value. `adversarial.py` already tests receiver mutation and index/RHS order; add the growth-boundary cross-product only after checking its exact capacity cases. Require OS-specific process capability gates. | P1 / M |

A follow-up local C audit also read `tests/bounded-runtime.c`, `tests/lazy-mmap-failure.c` and `tests/idle-service.c`, and inspected allocation routes in `runtime/minyar_heap.h`, `runtime/minyar_rc.h` and `runtime/minyar_runtime.c`. This narrowed the allocation recommendations below: startup failure injection, resize preservation, pool poisoning and allocation-triggered bounded service already exist. No uniform pairwise **configuration** manifest or systematic system-allocation ordinal campaign was found in the searched test sources; pairwise live-allocation overlap assertions are already present and are a different property.

### Ruby system decision and exclusions

Borrow pairwise **coverage accounting** and a behavior-first catalog. Minyar's existing feature-indexed conformance fixtures can carry explicit semantic clauses and “same contract across bootstrap/self-hosted/module paths” tags; no MSpec dependency or Ruby DSL is needed. Keep implementation-detail runtime tests separate from portable language behavior, so a future compiler/backend can reuse the latter.

Do not wholesale port Test::Unit/MSpec/bootstrap infrastructure. Minyar already uses Python subprocess/unittest runners; a second host language would raise maintenance cost. Ruby dynamic dispatch, coercion callbacks, arbitrary-precision integers, exception unwinding, mutable strings, tracing/compacting GC and thread/Ractor suites are not compatible semantics. Ruby tests that expect array out-of-range `nil`, negative indexing or automatic growth must become **rejection** cases only when Minyar's bounds contract calls for that behavior.

[Ruby COPYING](https://github.com/ruby/ruby/blob/b61936bc29156f6abff617f381d968a25b1a8e79/COPYING) offers the two-clause BSDL or Ruby-specific terms; [LEGAL](https://github.com/ruby/ruby/blob/b61936bc29156f6abff617f381d968a25b1a8e79/LEGAL) identifies exceptions. [Ruby Spec LICENSE](https://github.com/ruby/ruby/blob/b61936bc29156f6abff617f381d968a25b1a8e79/spec/ruby/LICENSE) and [MSpec LICENSE](https://github.com/ruby/ruby/blob/b61936bc29156f6abff617f381d968a25b1a8e79/spec/mspec/LICENSE) have their own notices. Do not label everything in this repository with one license when copying. This report copies no test implementation.

## Lua: inventory and inspected evidence

[Lua source](https://github.com/lua/lua/tree/0b29f408433e92953cc72b1d3e06c7ac8139e439) is compact enough to enumerate its test families directly. `testes/` contains 42 blob paths at this snapshot. The principal `.lua` files are `all`, `api`, `attrib`, `big`, `bitwise`, `bwcoercion`, `calls`, `closure`, `code`, `constructs`, `coroutine`, `cstack`, `db`, `errors`, `events`, `files`, `gc`, `gengc`, `goto`, `heavy`, `literals`, `locals`, `main`, `math`, `memerr`, `nextvar`, `pm`, `sort`, `strings`, `tpack`, `tracegc`, `utf8`, `vararg`, `verybig`. `testes/libs/` holds dynamically loaded C fixtures and a makefile; `packtests` packages the suite. Root `ltests.c`/`ltests.h` provide internal checks, controlled allocation and test-only access to VM data.

The [official test page](https://www.lua.org/tests/) distinguishes basic, complete and internal modes and warns that suites must match the Lua version. The current pinned runner identifies itself as Lua 5.5; source-main behavior should not be silently equated with a stable-release archive. Repository code is the primary evidence below.

Inspected [all.lua](https://github.com/lua/lua/blob/0b29f408433e92953cc72b1d3e06c7ac8139e439/testes/all.lua): suite version guard, `_soft`/`_port`/`_nomsg` controls, seed reporting, selected test sequencing and internal memory checks. Inspected [ltests.c](https://github.com/lua/lua/blob/0b29f408433e92953cc72b1d3e06c7ac8139e439/ltests.c): `debug_realloc` validates old size, can fail next/count-limited/byte-limited allocations, moves successful reallocations, marks freed/new memory and checks trailer guards. [memerr.lua](https://github.com/lua/lua/blob/0b29f408433e92953cc72b1d3e06c7ac8139e439/testes/memerr.lua) increments allocation count or memory allowance until a task succeeds, rejecting unexpected error classes. Also sampled [utf8.lua](https://github.com/lua/lua/blob/0b29f408433e92953cc72b1d3e06c7ac8139e439/testes/utf8.lua), [strings.lua](https://github.com/lua/lua/blob/0b29f408433e92953cc72b1d3e06c7ac8139e439/testes/strings.lua), [literals.lua](https://github.com/lua/lua/blob/0b29f408433e92953cc72b1d3e06c7ac8139e439/testes/literals.lua), [code.lua](https://github.com/lua/lua/blob/0b29f408433e92953cc72b1d3e06c7ac8139e439/testes/code.lua), [cstack.lua](https://github.com/lua/lua/blob/0b29f408433e92953cc72b1d3e06c7ac8139e439/testes/cstack.lua), [files.lua](https://github.com/lua/lua/blob/0b29f408433e92953cc72b1d3e06c7ac8139e439/testes/files.lua), [math.lua](https://github.com/lua/lua/blob/0b29f408433e92953cc72b1d3e06c7ac8139e439/testes/math.lua). Coroutine/GC/metatable tests were inventoried, not substantively audited.

### Nine concrete Lua-derived candidates

| Candidate and origin | Minyar translation and incremental gap | Priority / cost |
|---|---|---|
| Every-allocation failure sweep (`memerr.lua:testalloc`) | Add a test allocator that rejects allocation N, iterate N until List-growth/Text-join/record-construction workload succeeds, require specified allocation error each failed run. Minyar terminates on runtime errors: use fresh subprocesses, do not assume Lua `pcall` recovery. `tests/lazy-mmap-failure.c` already injects each of two startup mapping failures and verifies rollback, and `tests/lazy-configurations.py` runs those natively/sanitized. Those targeted failpoints and existing pool exhaustion are not a systematic system-allocator ordinal sweep; extend the established injection approach. | P1 / M |
| Byte-budget sweep (`memerr.lua:testbytes`) | For tiny selected workloads, sweep a bounded set of allocator byte limits around measured success threshold and verify clean termination/output atomicity. Use deterministic test limits rather than host OOM. Existing finite-heap profiles plus `bounded-runtime.c` already cover exact-capacity resize, fragmentation and debt exhaustion; the delta is controlled byte-budget steps for individual system-allocator operation intermediates, not generic heap capacity boundaries. Do not adopt Lua's hard-coded step of seven or GC recovery expectations as Minyar contracts. | P2 / M |
| Always-moving realloc (`ltests.c:debug_realloc`) | Test-only allocator always moves a grown buffer and poisons/frees the old allocation. The extra axis is forcing **system** realloc to move every time while language-level aliases remain live, not introducing resize correctness tests. | Allocator wrapper self-check (`ltests.c` size/guard checks) | Deliberately corrupt a test allocation trailer and pass an incorrect old-size value, require the wrapper to fail before trusting its results. | UTF-8 metamorphic decomposition (`utf8.lua:check`) | For each valid scalar sequence, `joinText` of all one-scalar slices equals the source; every slice length equals end-start; concatenated split slices equal original. | Error-position UTF-8 matrix (`utf8.lua:checklen`) | Put the same malformed byte sequence before/mid/after valid mixed-width prefixes. ### Lua system decision and exclusions

The **controlled allocator plus ordinal-failure campaign** is the highest-value portable methodology in this audit. Build a small Minyar C test hook, preserve the established independent ownership model, and run faulting workloads in subprocesses. Keep exact allocation-count assertions restricted to deliberately stable optimization contracts; ordinary semantic tests should tolerate allocation strategy changes. Record seed, ordinal, requested sizes and failing operation in retained evidence.

Do not import Lua's `T`/testC mini-language, Lua assertion suite or VM introspection harness wholesale. Minyar emits LLVM and has a different runtime ABI. Lua's collector/incremental/generational tests do not prove reference-count reclamation, Lua's byte-string operations do not specify Unicode Text, and Lua's wrapping integer arithmetic, floor division, truthiness, dynamic tables, coroutines, metatables and error recovery should not be copied as expectations. Opcode list/constant-table tests can inspire local emitted-LLVM invariants, but Lua opcodes themselves are irrelevant.

Lua test files reference the [copyright/license notice in lua.h](https://github.com/lua/lua/blob/0b29f408433e92953cc72b1d3e06c7ac8139e439/lua.h), which grants MIT-style permissions conditioned on preservation of copyright and permission notice. Record exact source SHA/path and modifications if any test/helper is adapted. This report recommends independently written Minyar scenarios; it copied no implementation.

## Suggested order

1. Pilot Lua-style ordinal allocation failures and forced relocation against the existing system runtime test build; inject a known bad allocator interaction to prove the harness detects it.
2. Extend shared-Text backing, UTF-8 and List-growth/receiver tests with the precise cross-products above.
3. Audit configuration pair coverage and make skipped internal/capability coverage visible.
4. Add descendant-process cleanup self-tests to existing retained-evidence runners.

Each item needs a final local coverage check before implementation: a matching test may exist outside the sampled fixtures. Existing independent graph oracles, sanitizer checks and real execution remain the primary correctness evidence.
