Audit date: 2026-10-04. Scope: source inspection and adoption assessment, not execution of upstream suites or implementation of proposed tests.

This is a detailed representative audit, **not a claim to have read every upstream test**. Broad inventories establish where tests live; the linked cases and harness functions below establish the recommendations. No upstream compiler was built and no upstream suite was run. Source snapshots were inspected in a temporary directory; this report and its immutable links are the retained research artifact.

Local comparison read `README.md`, `docs/language.md`, `docs/testing.md`, Makefile targets, full diagnostic/conformance runners, the incremental driver suite, and relevant regression, adversarial, runtime and allocator sections. Searches across `tests`, `scripts` and `runtime` supplemented those reads. “Gap candidate” means no equivalent was identified within this inspection; it is not proof of absence from every generated campaign.

Minyar already has unusually substantial testing: byte-exact diagnostics (including columns and absence of stale LLVM output), O0/O2 conformance, generated typed programs and arithmetic oracles, ownership/alias models, sanitizers, finite-pool stress, mutation testing, self-host fixed points, and multi-platform CI. Its incremental driver already tests preserved-mtime edits, malformed/checksummed cache data, compiler identity changes, publication failures, concurrent builds and Unicode paths. Recommendations below add specific dimensions rather than relabel these existing capabilities.

Priorities: **P1** = next targeted testing improvement; **P2** = useful after P1; **defer** = feature or contract prerequisite. Effort estimates are engineering estimates: S = roughly half to two days, M = roughly three to seven days including meaningful harness tests. Estimates are not benchmark results.

## Rust

### Test landscape and inspected implementation

The returned tree includes UI, MIR optimization, LLVM codegen, assembly, incremental compilation, debugger, coverage, crash regression, run-make, run-make-cargo, pretty-printing and multiple rustdoc suites. Rust library tests and tool-specific suites are additional locations; the truncated inventory must not be mistaken for a complete listing.

[UI runner implementation](https://github.com/rust-lang/rust/blob/56343b1a7d3fed3f349a5c2dc474f65b504f5221/src/tools/compiletest/src/runtest/ui.rs) separates compiler-output comparison from execution-output comparison and supports revision-specific expected files. It explicitly rejects truncated compiler output before comparison. [Run-make implementation](https://github.com/rust-lang/rust/blob/56343b1a7d3fed3f349a5c2dc474f65b504f5221/src/tools/compiletest/src/runtest/run_make.rs) supplies a compiled Rust scenario driver with compiler/tool context. These are different levels: UI is a source fixture plus expected behavior; run-make is an integration scenario spanning artifacts and subprocesses.

[Miri's README](https://github.com/rust-lang/rust/blob/56343b1a7d3fed3f349a5c2dc474f65b504f5221/src/tools/miri/README.md) describes a Rust interpreter detecting undefined behavior in particular executions, with isolation and cross-target interpretation. It is neither a general LLVM sanitizer nor a drop-in runtime oracle for Minyar. Its documented passing-test limits matter: passing one interpreted execution does not prove universal soundness.

**Decision:** lightly adapt revision metadata and explicit fixture modes around Python. Keep source/expected-output files readable. A minimal schema can express compile-fail, run-pass and run-fail plus optimization/profile variants; multi-file scenarios remain Python. Importing compiletest would introduce Rust bootstrap/compiler-specific machinery without replacing Minyar's ownership or cache oracles. Do not adopt Miri itself: a Minyar interpreter would be a separate major project. Existing independent ownership models plus native sanitizer execution already deliver the closest immediately applicable methodology.

Defer Rust borrow checking, lifetime inference, trait solver, generics, rustdoc, unsafe provenance and concurrent memory-model fixtures: those are not Minyar language contracts. MIR-specific snapshots do not translate to Minyar's direct LLVM pipeline. Selective LLVM invariants can use the project's existing structural tests, without snapshotting whole optimization-sensitive IR files.

## Go

### Test landscape and inspected implementation

Go distributes tests across the top-level `test/` compiler regression corpus, package-local `*_test.go` files (compiler, runtime, standard library), command integration scenarios, and support/testdata trees. Codegen and historical fixedbugs cases are distinct from runtime unit tests and command/cache integration.

The inspected [compiler test-directory harness](https://github.com/golang/go/blob/6f5c275ebdc454197fff5f1496521c8f81e20eef/src/cmd/internal/testdir/testdir_test.go) interprets test actions such as execution and diagnostic/codegen checking. The [command script harness](https://github.com/golang/go/blob/6f5c275ebdc454197fff5f1496521c8f81e20eef/src/cmd/go/script_test.go) discovers scripts, runs independent temporary workspaces, extracts embedded files, supports selective subtest execution and budgets termination grace periods. The [script README](https://github.com/golang/go/blob/6f5c275ebdc454197fff5f1496521c8f81e20eef/src/cmd/go/testdata/script/README) documents expectations and fixtures. This is a concrete way to make multi-file regressions reviewable, not a reason to add Go tooling to Minyar.

## Zig

### Test landscape and inspected implementation

The complete tree includes `test/cases` (1,161 blobs), `test/behavior` (168), `test/standalone` (233), `test/link` (52), `test/incremental` (34), C ABI, CLI, error/stack traces, LLVM target/IR and standard-library colocated tests. These counts include support inputs, not only executable test cases.

[Cases.zig](https://github.com/ziglang/zig/blob/738d2be9d6b6ef3ff3559130c05159ef53336224/test/src/Cases.zig) parses source-embedded expected-result/configuration metadata and expands target/backend combinations. [tests.zig](https://github.com/ziglang/zig/blob/738d2be9d6b6ef3ff3559130c05159ef53336224/test/tests.zig) constructs module, standalone, linker, incremental and other suites; [compile_errors.zig](https://github.com/ziglang/zig/blob/738d2be9d6b6ef3ff3559130c05159ef53336224/test/compile_errors.zig) is additional compile-error infrastructure. Behavior examples were inspected in `array.zig`, `while.zig`, and `eval.zig`; many compile-time or specialized loop constructs are not applicable.

The most useful new technique is [checkAllAllocationFailures](https://github.com/ziglang/zig/blob/738d2be9d6b6ef3ff3559130c05159ef53336224/lib/std/testing.zig): first establish the successful allocation count, then replay with each allocation ordinal forced to fail. It detects swallowed OOM, nondeterministic allocation paths and leaked allocations on error. [FailingAllocator.zig](https://github.com/ziglang/zig/blob/738d2be9d6b6ef3ff3559130c05159ef53336224/lib/std/testing/FailingAllocator.zig) separately controls allocation and resize failure. The automatic sweep in `checkAllAllocationFailures` is of **allocation** indices; resize failures need their own scenarios.

**Decision:** adopt the failure-injection methodology, implemented as minimal test-only hooks around Minyar's C allocation layer, not a Zig dependency. Start with deterministic small operations and system allocation; then decide how to expose pool allocation attempts. Each injected failure must actually occur, otherwise the case is inconclusive/failing. Include a harness test that intentionally swallows a failure and one that changes allocation count, so the campaign cannot report vacuous success. Keep hooks out of production builds and test that ordinary builds do not enable them.

Minyar's documented fatal OOM/exit behavior is the crucial difference from Zig's recoverable `error.OutOfMemory` and `errdefer`: counting all outstanding process memory as a leak after fatal exit would invent a stronger contract. Assert cleanup only on recoverable lower-level APIs or successful final drain. Do not rewrite language error semantics to make an imported harness pass.

Defer compile-time execution, pointer arithmetic, arbitrary-width integers, vectors, error unions, async and Zig's multiple backends. Keep target/profile matrices bounded; Minyar already has expensive sanitizer/profile combinations, and a Cartesian product of every input and variant would dilute useful feedback.

## Combined implementation recommendation

1. **Add targeted regressions first (P1/S):** huge List indices for reads/writes; unreachable trapping expression; unused overflowing local; Unicode diagnostic columns. Each should fail under a deliberately broken relevant check if practical, and run against normal O0/O2 configurations. These are hypotheses to reconcile with existing generated cases, not discovered compiler bugs.
2. **Pilot allocation failure injection (P1/M):** one Text operation, one nested constructor, one resize scenario. Record baseline allocation count, injected index, command, stderr/status and sanitizer result. Validate the injector itself before broadening. Existing finite-pool tests remain valuable and distinct.
3. **Improve fixture organization only where it reduces repeated work (P2/M):** add narrow modes/revisions to existing Python runners, reuse process-group timeout/evidence code, and migrate only a handful of representative cases initially. Preserve existing exact diagnostics and rich cache counters. Do not introduce three foreign harnesses.
4. **Audit warm/cold diagnostics and stage invalidation (P1–P2/S):** choose public launcher scenarios not already covered by direct-frontend tests; compare both, so fallback cannot conceal incremental failures.

Acceptance for any harness change: a real passing case plus deliberately wrong status, wrong output, missing variant, timeout/descendant, stale artifact and missing golden cases must be rejected. Report pass/fail/skip distinctly and retain reproduction inputs on failure. Existing `memory-contracts` and mutation harness tests provide a local pattern to reuse.
