# CPython and Swift testing audit for Minyar

Research retrieved 2026-10-04. This is an inventory and sampled source audit, not a claim to have read every test or run either upstream suite. GitHub recursive trees were complete (`truncated: false`): CPython 6,955 entries; Swift 35,551 entries, including directories and non-test files. Main-branch snapshots: CPython `9d22a5334bd5273962adceeb697a1337e9a0ca21`, Swift `6b8daddf6f30bb1bbdcaaede7f673e76eb155278`. All upstream links below are pinned.

## Local baseline and scope

Read `README.md`, `docs/language.md`, `docs/testing.md`, `Makefile`, `tests/conformance.py`, `tests/diagnostics.py`, `tests/regressions.py`; inspected relevant sections/search matches in `tests/adversarial.py`, `tests/runtime-unit.c`, and incremental module suites. Minyar already has O0/O2 execution, exact diagnostic goldens, deterministic generated programs, coverage and mutation floors, sanitizer jobs, ownership graph models, cache invalidation, stack guards and compiler fixed points. Recommendations below extend these; they do not propose introducing them again. “Gap” means absent from this inspected coverage, not a proof of absence from every fixture.

Cost estimates: S = roughly half to two engineering days; M = three to five days; L = more than a week, including checks of the harness. P1 = useful near-term; P2 = scheduled extension; P3 = defer. No test code was copied or implementation changed.

## CPython inventory

The [complete source tree](https://github.com/python/cpython/tree/9d22a5334bd5273962adceeb697a1337e9a0ca21) places language, built-in, standard-library, regression and platform tests under `Lib/test/`; package subtrees include `test_capi`, `test_ctypes`, `test_importlib`, `test_asyncio`, `test_free_threading`, and `test_tools`. Native extension test hooks reside in `Modules/_testcapi`, `_testinternalcapi` and other `_test*` modules. `Lib/test/support` provides resource, subprocess and platform helpers; `Lib/test/libregrtest` is the orchestration layer. `Lib/test/test_regrtest.py` tests that layer. `Modules/_xxtestfuzz` contains native fuzz targets, dictionaries and corpora; `.github/workflows/reusable-cifuzz.yml` wires a fuzzing job. `Tools/freeze/test` is a separate tool integration suite. Documentation doctests and external ecosystem tests were not exhaustively enumerated.

Inspected representative source:

- [runner options](https://github.com/python/cpython/blob/9d22a5334bd5273962adceeb697a1337e9a0ca21/Lib/test/libregrtest/cmdline.py): seeded order randomization, subprocess workers, resource selection, repeated reference-leak runs, failure bisection, CI presets.
- [environment guard](https://github.com/python/cpython/blob/9d22a5334bd5273962adceeb697a1337e9a0ca21/Lib/test/libregrtest/save_env.py): snapshots/restores process resources and reports contamination.
- [reference-leak runner](https://github.com/python/cpython/blob/9d22a5334bd5273962adceeb697a1337e9a0ca21/Lib/test/libregrtest/refleak.py): cache warmup followed by repeated refcount/allocation observations.
- [compiler regressions](https://github.com/python/cpython/blob/9d22a5334bd5273962adceeb697a1337e9a0ca21/Lib/test/test_compile.py): missing final newline, newline variants, nulls, allocation failure, evaluation order, constant merging, recursion and dead blocks.
- [codec cases](https://github.com/python/cpython/blob/9d22a5334bd5273962adceeb697a1337e9a0ca21/Lib/test/test_codecs.py), [integer tests](https://github.com/python/cpython/blob/9d22a5334bd5273962adceeb697a1337e9a0ca21/Lib/test/test_long.py), [list tests](https://github.com/python/cpython/blob/9d22a5334bd5273962adceeb697a1337e9a0ca21/Lib/test/test_list.py), [tokenizer tests](https://github.com/python/cpython/blob/9d22a5334bd5273962adceeb697a1337e9a0ca21/Lib/test/test_tokenize.py): downloaded and sampled relevant cases, not every assertion.

### Concrete CPython-derived candidates

| Candidate and upstream inspiration | Minyar adaptation and coverage delta | Priority / cost |
|---|---|---|
| Exhaustive malformed UTF-8 classes (`test_codecs.py`) | Generate every truncated prefix length, isolated continuation bytes, overlong width, surrogate edge and >U+10FFFF edge. Apply the same corpus to source ingestion, file reads and arguments where representable. `regressions.py` currently checks four malformed file byte sequences; expand the matrix rather than add another generic Unicode test. Minyar must reject invalid scalar encoding, never use Python's `surrogatepass` behavior. | P1 / S |
| Valid scalar boundaries (`test_codecs.py`) | Already covered: `tests/runtime-unit.c:332–340` tests exactly NUL, U+007F/0080/07FF/0800/D7FF/E000/FFFF/10000/10FFFF through Character→Text→index/length. The remaining proposal is composing those scalars into mixed-width sequences and exercising slices, joins, source ingestion and file I/O; do not duplicate the existing scalar round-trip. Python permits isolated surrogates in strings; exclude those from valid Minyar values. | P1 / S |
| Newline/token-boundary matrix (`test_compile.py`, `test_tokenize.py`) | Cross LF/CRLF, final newline/no newline, comments after continued operators and nested call/list continuations. Assert execution plus exact error location for forbidden forms. Existing newline fixtures and module normalization do not establish this full cross-product. Bare CR acceptance needs a documented Minyar decision before adopting that Python expectation. | P1 / S |
| Embedded source NUL (`test_compile.py:test_null_terminated`) | Insert NUL before/after a valid statement and inside comments, identifiers and literals. Source must not silently truncate a malicious suffix; distinguish valid escaped Text NUL from malformed source bytes. Exact status/no output artifact. General hostile-input fuzz is already present; add named regressions with specified lexical behavior. | P1 / S |
| Signed division/remainder identities (`test_long.py`) | Generate bounded signed operands around powers of two and Integer extrema; calculate truncation-toward-zero expectations explicitly, check `a=q*b+r` only with safe intermediate arithmetic. Never use Python `//` or `%` as the direct oracle for negative operands. Existing arithmetic oracles reduce novelty; audit their sign/boundary corpus before adding. | P2 / S |
| List allocation-failure points (`test_list.py:test_no_memory`) | Inject failures at growth allocations and check deterministic failure/no corrupt publication. Use C runtime harness for exact failpoint control, not enormous host allocations. Existing fixed/lazy exhaustion and independent ownership models cover general exhaustion; delta is per-allocation failure-position coverage for system allocation. | P2 / M |
| Seeded suite-order contamination (`cmdline.py`, `save_env.py`) | Run selected Python harnesses under multiple logged orders and shared launcher/cache workspace where sharing is intentional; verify environment/cwd/files return to baseline. Current suites use temporary dirs but no uniform order/environment audit was found. Separate processes cannot detect Python-global leakage in each other; focus on persistent cache/files/process descendants. | P1 / M |
| Warmup then repeated lifetime baseline (`refleak.py`) | Repeat one allocation/slice/list workload hundreds of times in the same C runtime process, drain bounded debt between rounds, and assert live nonimmortal objects/storage return to the warmed baseline. Current terminal cleanup and immortal-cache assertions are stronger than RSS alone; delta is per-round drift localization. Never claim compiler-arena mode leaks by this metric. | P2 / M |
| Harness resource-policy test (`cmdline.py`, `test_regrtest.py` inventory) | A single declared slow/native-only/sanitizer capability manifest should prove the portable gate does not silently omit a required test or invoke unsupported resource-heavy suites. Existing Make targets separate budgets; add machine-readable skipped reasons and self-tests for classification. | P2 / M |

### System decision

Do **not** vendor `libregrtest`: it assumes CPython internals, Python module tests and interpreter-specific resource cleanup. Adapt its seed/replay, contamination and failure-classification concepts to existing Python subprocess runners. Do not replace Minyar's precise ownership oracle with CPython reference-count totals or RSS. CPython's fuzz harness integration is less valuable than extending Minyar's already established AFL++ and deterministic fuzz coverage. Defer Python dynamic object callbacks, GC cycles, arbitrary-precision integers, exceptions, threads and expansive standard-library suites: they test semantics Minyar does not have.

CPython's [LICENSE](https://github.com/python/cpython/blob/9d22a5334bd5273962adceeb697a1337e9a0ca21/LICENSE) includes the PSF license and historical notices. New tests independently written from behavior avoid a wholesale copy; if adapting actual code or fixtures, retain applicable attribution/license text and record source SHA, path and modifications. Check per-file third-party provenance as well.

## Swift inventory

[Swift's source tree](https://github.com/swiftlang/swift/tree/6b8daddf6f30bb1bbdcaaede7f673e76eb155278) separates `test/` lit-driven regression tests, `validation-test/` larger executable/stdlib/crasher validation, `unittests/` C++ component tests, `benchmark/` performance material, and private stdlib test support under `stdlib/private/StdlibUnittest`. Major families inventoried include Parse, Sema, Constraints, SILGen, SILOptimizer, IRGen, Serialization, ModuleInterface, Driver, ScanDependencies, Runtime, stdlib, Sanitizers, reproducible-builds, DebugInfo, IDE/SourceKit and interoperability. Validation also contains both unfixed compiler crashers and fixed crashers: these should not be treated as equally passing regression suites. Concurrency, macros, generics, Swift ABI and Objective-C/C++ interoperability were inventoried but not deeply audited for Minyar.

Inspected:

### Concrete Swift-derived candidates

| Candidate | Minyar adaptation and coverage delta | Priority / cost |
|---|---|---|
| Breadcrumb threshold matrix (`StringBreadcrumbs.swift`) | Probe scalar indexes 63/64/65 and multiple table boundaries with all UTF-8 widths, descending/random accesses and nested slices. `runtime-unit.c:109–129` already constructs 130 two-byte scalars, checks indexes 63/64/129, checks every forward index with exactly 130 decodes, and checks a 63–65 slice. The gap is mixed-width content, descending/random access, and nested slices spanning breadcrumb boundaries; basic boundaries and linear forward decoding are covered. Swift UTF-16/grapheme expectations must become scalar-index expectations. | P1 / S |
| Optimized signed division traps (`IntegerDivisionTraps.swift`) | Upstream exercises `dividingFullWidth((high, low))`; Minyar has no equivalent primitive. Borrow only its isolated-trap testing methodology: independently design ordinary Minyar zero-divisor and MIN/-1 cases with required status/message, O0/O2, literal and function-return operands. Existing overflow/divide fixtures cover basics; confirm variable-vs-constant and sign matrix coverage before insertion. Swift's signal/trap status is not Minyar's expected error contract. | P1 / S |
| Reduced-width exhaustive division oracle (`IntegerDivision.swift`) | Upstream exhaustively/sampled-tests `dividingFullWidth((high, low))`, including Int8/UInt8; Minyar lacks both that full-width primitive and those integer types. Borrow only the enumeration technique: independently enumerate a small signed subdomain of Minyar Integer and add ordinary 64-bit boundary samples, comparing quotient/remainder. Existing fuzz samples do not substitute for exhaustive small-domain enumeration. | P2 / S |
| Per-function ownership IR assertions (`arcsequenceopts.sil`) | Isolate one Minyar function per regression; assert retain/release/stack-owner shape scoped to its emitted LLVM function plus execute an ownership oracle. Current scalar/ownership tests already inspect IR: source-adjacent positive/negative matching can reduce scattered brittle regexes. Do not import SIL or introduce another IR. | P1 / M |
| Explicit flaky failure fixture (`swift_test.py`) | Simulate fail→pass and timeout→pass harness commands; preserve first failure log, classify flaky as failing, and never green a retry. Existing memory/mutation runner self-tests inject hard failure/hang but no unified flaky classification was found. Only add retries for diagnosis, not acceptance. | P1 / S |
| Dependency change sequence (`module_deps_invalidate.swift`) | Extend existing incremental tests with add→remove→restore transitive edge plus cold/reference output after each step, preserving an unaffected branch. Current graph-edit and corruption coverage already exists; delta is a single adversarial sequence with exact per-step rebuild/reuse observations. | P2 / M |
| Cross-root reproducibility (`swiftc-emit-ir.swift`) | Existing fixed points/determinism compare compiler outputs; add identical source trees in distinct temp roots, shuffled creation order and cold/warm caches. Compare normalized artifacts only after documenting legitimate path fields; execute both. This extends Swift's same-path repeat check, rather than assuming it establishes relocation reproducibility. | P2 / M |
| Per-phase lifetime ledger (`LifetimeTracked.swift`) | Instrument test runtime allocation IDs with alive/dead states at selected statement/scope checkpoints; test alias retains, returns and double destruction. Existing exact graph models already cover lifetime totals, so add only if allocation-identity traces improve localization of a surviving mutation. Swift immediate deinit timing is incompatible with Minyar bounded deferred cleanup; assert after explicit test drains. | P2 / M |
| Diagnostic expectation maintenance (`verify.swift`) | Prototype a small optional source-adjacent expected diagnostic format for generated/reduced crash reproducers, with strict unexpected-diagnostic rejection and orphan expectation self-tests. Preserve existing byte-for-byte goldens for wording/column contracts. Adoption is a maintainability pilot, not missing diagnostic coverage. | P3 / M |

### System decision

Do not import Swift's entire testing stack or `StdlibUnittest`: it depends on Swift language features and compiler/build substitutions. A bounded **lit/FileCheck pilot** is reasonable for new LLVM-shape fixtures if LLVM tooling is already managed; compare it against a tiny existing-Python matcher and adopt only if it reduces dependency and maintenance burden overall. Preserve O0/O2 native execution and independent ownership models because textual IR checks cannot prove behavior. Swift's explicit `FLAKYFAIL` handling is immediately portable as a policy.

Reject direct transfer of Swift Array copy-on-write expectations (Minyar Lists are shared mutable references), Character grapheme indexing (Minyar Character is one scalar), canonical-equivalence String assumptions without a Minyar specification, ARC destructor timing, Swift generic/async/macro tests, or signal-based trap contracts. Do not copy known-failing crasher corpora into a required-green suite without classifying expectations.

Swift's [LICENSE.txt](https://github.com/swiftlang/swift/blob/6b8daddf6f30bb1bbdcaaede7f673e76eb155278/LICENSE.txt) is Apache 2.0 with Runtime Library Exception; sampled source files carry corresponding notices. Preserve notices and provenance for copied tests; independently translating a semantic scenario is preferable. An external lit/FileCheck dependency needs its own pinned LLVM package/license record.

## Recommended first batch

1. Add precise UTF-8 boundary/corruption matrices and multi-boundary Text breadcrumb cases to existing suites.
2. Add harness self-tests proving failure→pass remains failing and suite-order/cache contamination is reproducible.
3. Audit existing arithmetic oracles before adding small-domain exhaustive division and full signed trap matrices.
4. Pilot source-adjacent ownership IR checks on a few existing regressions, keeping runtime proof; decide whether lit actually earns its dependency.

These are research proposals, not verified bugs or test implementations. No upstream suite was executed; source retrieval and local coverage inspection establish relevance, not that every proposed gap is a current defect.
