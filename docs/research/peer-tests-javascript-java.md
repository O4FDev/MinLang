## JavaScript: suite map and decisions

Test262's immediate test roots are `language`, `built-ins`, `annexB`, `intl402`, `harness`, and `staging`. The first holds grammar and language semantics; the others cover the standard library, compatibility semantics, internationalization, harness assertions, and less formal staging cases. `src` holds generated case/template inputs; `harness` holds helpers; `tools` supports maintenance. The [authoring contract](https://github.com/tc39/test262/blob/7ab7fafa0003f73fc85c1b95d88094d33f7eb8bd/CONTRIBUTING.md) associates cases with specification anchors, required features, negative phases, and generated provenance. This is the valuable part for Minyar: a checked, machine-readable version of our existing prose conformance index.

The [execution contract](https://github.com/tc39/test262/blob/7ab7fafa0003f73fc85c1b95d88094d33f7eb8bd/INTERPRETING.md) distinguishes parse, module-resolution, and runtime failures and requires isolated execution environments. Minyar already starts native executables separately and its diagnostic runner requires status 1 and no LLVM output. Extend those controls consistently across the public launcher and module driver. Do not claim our frontend can distinguish parser and type-checker phases externally without adding that interface.

V8 adds engine-specific `mjsunit`, C++ `cctest`/`unittests`, `message`, `filecheck`, fuzzing (`fuzzer`, `fuzzilli`), debugger/inspector, memory, bigint, internationalization, performance, and imported compatibility suites. WebAssembly roots and Torque tests concern additional implementation languages; they do not count as extra languages in this audit. The [mjsunit adapter](https://github.com/v8/v8/blob/7dce5a4a324258ba51b2a6f5dee7a1fa18c7671d/test/mjsunit/testcfg.py) parses source flags and environment requirements; [variants](https://github.com/v8/v8/blob/7dce5a4a324258ba51b2a6f5dee7a1fa18c7671d/tools/testrunner/local/variants.py) centralize execution configurations; [status handling](https://github.com/v8/v8/blob/7dce5a4a324258ba51b2a6f5dee7a1fa18c7671d/tools/testrunner/local/statusfile.py) separates failures, timeouts, crashes, and configuration exclusions.

**Decision:** adapt metadata, variant selection, and small semantic cases. Do not import Test262 or V8's runner. They require JavaScript execution, host APIs, and engine controls which Minyar does not expose. In particular, V8's combined-test implementation explicitly accepts PASS or TIMEOUT; it does not thereby accept crashes. Its JIT-fuzzing variants separately suppress ordinary assertion failures to focus on engine checks/crashes. Neither relaxed policy belongs in Minyar's semantic correctness gate: wrong results, crashes and timeouts must remain failures.

## Java: suite map and decisions

OpenJDK organizes compiler tests under `test/langtools` (javac, javadoc, jshell and related tools), runtime/compiler tests under `test/hotspot/jtreg`, VM unit tests under `test/hotspot/gtest`, and Java library tests under `test/jdk`. Other roots include `jaxp`, `micro`, `benchmarks`, documentation/build tests, shared `lib`/`lib-test`, failure handling, and jtreg support extensions. Inventorying a directory is not evidence of reviewing its contents; this audit samples javac flow analysis and HotSpot optimizer testing, not GUI, networking, every library, or the whole VM.

The [testing guide](https://github.com/openjdk/jdk/blob/f3701c80216900f3ded26f9de1befe43813be95c/doc/testing.md) explains selection and tiering. [HotSpot groups](https://github.com/openjdk/jdk/blob/f3701c80216900f3ded26f9de1befe43813be95c/test/hotspot/jtreg/TEST.groups) and [langtools groups](https://github.com/openjdk/jdk/blob/f3701c80216900f3ded26f9de1befe43813be95c/test/langtools/TEST.groups) encode selections. Minyar already has smoke, portable, full, memory levels, and nightly fuzzing; the useful next step is machine-checkable membership and runtime reporting, not merely adding more tier names.

The [IR framework](https://github.com/openjdk/jdk/blob/f3701c80216900f3ded26f9de1befe43813be95c/test/hotspot/jtreg/compiler/lib/ir_framework/README.md) couples functional checks to required/forbidden IR patterns and gates structural checks by platform/configuration. Its [implementation](https://github.com/openjdk/jdk/blob/f3701c80216900f3ded26f9de1befe43813be95c/test/hotspot/jtreg/compiler/lib/ir_framework/TestFramework.java) controls separate test VMs and scenarios. Minyar can use this discipline with emitted LLVM and its existing structural assertions, without Java annotations, JIT warmup, or JVM orchestration.

**Decision:** adapt narrow cases, tier accounting, and conditional structural assertions. Do not import jtreg or the HotSpot IR framework as runtime dependencies. A standalone FileCheck pilot is a better fit for Minyar's LLVM output; see the C++ report.

## Import provenance

The sampled Test262 files carry BSD notices; its [LICENSE](https://github.com/tc39/test262/blob/7ab7fafa0003f73fc85c1b95d88094d33f7eb8bd/LICENSE) also distinguishes materials. V8 has a [BSD-style license](https://github.com/v8/v8/blob/7dce5a4a324258ba51b2a6f5dee7a1fa18c7671d/LICENSE). The sampled HotSpot tests and `ConstantInfiniteWhile.java` carry GPLv2-only headers; `T8156180.java` instead has a `/nodynamiccopyright/` marker and no such header. Inspect each file rather than assuming the project-level Classpath exception covers tests. No code is copied by this research. The recommended first implementation is original Minyar fixtures derived from the behavioral requirement, with upstream issue/source links. Any later verbatim import needs its exact source revision, file notices, and license recorded.

## Independent review

A second agent independently read the Test262 addition/division/coalesce fixtures and execution metadata, V8's escape-analysis fixture, combined-test adapter, status categories and variants, and OpenJDK's div/mod, zero-check, multiplication, javac reference and IR-framework sources. It rechecked the local conformance/diagnostic helpers, arithmetic oracle, short-circuit fixtures, language return rules, and division/remainder lowering. All 30 distinct linked GitHub blob files were fetched successfully at their pinned revisions; this confirms file availability, not the behavior of the test suites. Saved subtree manifests confirm the 24,443 and 11,489 inventory-entry counts with `truncated: false`.

Corrections from that review: V8's combined mode explicitly tolerates timeouts, not crashes; the V8 escape fixture returns a Boolean rather than an escaping record; MIN/-1 remainder rejection is implemented but deserves an explicit language-specification decision; the javac fixture without a copyright header must not be described as carrying one. The pinned `ConstantInfiniteWhile.java` contains two block-comment openings and only one closure, leaving the test metadata comment unterminated. A fresh upstream fetch reproduced those bytes. We therefore retain J6 only as a conditional idea inspired by the historical test's stated intent, not evidence of a functioning upstream positive test. No upstream or Minyar test suite was run for this review.
